### 二、Git 全局配置

#### 1、配置命令
```
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

#### 2、配置原理
Git 全局配置保存在用户主目录下的 `.gitconfig` 文件中，定义所有仓库共享的默认属性。提交时 Git 将 `user.name` 与 `user.email` 写入 commit 元数据中，用于追溯作者。

### 四、Conda 虚拟环境

#### 1、创建与激活
```
conda create -n oj python=3.11 -y
conda activate oj
```

#### 2、虚拟环境原理
Conda 虚拟环境本质上是独立的目录树，包含独立的 Python 解释器、site-packages 与可执行脚本。激活时 Conda 修改 `PATH` 环境变量，使 shell 优先使用该环境的解释器。

#### 3、通用命令

| 操作 | 命令 |
|---|---|
| 创建环境 | `conda create -n 环境名 python=版本` |
| 激活环境 | `conda activate 环境名` |
| 退出环境 | `conda deactivate` |
| 列出环境 | `conda env list` |
| 删除环境 | `conda env remove -n 环境名` |

### 六、通用性原则

1. **环境隔离原则**：任何项目都应使用独立的虚拟环境，避免全局依赖污染。
2. **配置与代码分离原则**：敏感信息应通过环境变量或 `.env` 文件提供，不应硬编码在源码中。
3. **可重现性原则**：项目依赖应通过 `requirements.txt` 显式锁定版本。

### 七、注意事项

#### 1、Docker Desktop 安装
- 安装完成后**必须重启电脑**，否则 Docker 服务无法正常启动。
- 确保任务栏右下角有 Docker 鲸鱼图标，处于运行状态。

#### 2、Conda 环境激活
- 每次打开新的终端，都需要执行 `conda activate oj`，否则会使用默认的 base 环境。
- 终端提示符应显示 `(oj)` 前缀，如 `(oj) E:\...>`。

#### 3、Git 配置
- `user.name` 和 `user.email` 是全局配置，只配置一次即可。
- 邮箱应与 GitHub 注册邮箱一致，否则提交不会关联到 GitHub 账户。

#### 4、路径选择
- 项目路径避免包含中文和空格，推荐使用类似 `E:\github_project\oj-platform` 的纯英文路径。
- 本项目统一使用 `E:\github_project\oj-platform`。
