### 一、SQLAlchemy 2.0 基础配置

#### 1、数据库引擎与会话
```python
# backend/app/database.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from sqlalchemy.orm import DeclarativeBase
from app.core.config import settings

engine = create_async_engine(settings.DATABASE_URL, echo=False)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

class Base(DeclarativeBase):
    pass
```

#### 2、组件职责

| 组件 | 职责 |
|---|---|
| engine | 管理数据库连接池 |
| async_session | 会话工厂，每次调用产生一个 AsyncSession |
| Base | 所有 ORM 模型的基类，维护元数据 metadata |

`expire_on_commit=False` 保证提交后对象属性仍可读取，否则访问未刷新属性会触发额外查询。

### 三、设计决策的通用性原则

#### 1、主表与子表分离
五种题型的数据结构不同：算法题需要多个测试用例，科研项目需要多个子项目，而选择题和填空题的选项/空位结构相对简单。子表分离避免空值列过多。

#### 2、弱结构化数据用 JSONB
标签、选项、空位等结构灵活且长度不定的数据，使用 PostgreSQL 的 JSONB 类型存储，避免频繁建表。JSONB 提供索引支持（GIN 索引）和包含查询（contains 操作符）。

#### 3、级联删除
子表的外键使用 `ondelete="CASCADE"`，删除题目时自动删除关联的测试用例、子项目和图片，避免孤儿数据。

#### 4、时间戳由数据库生成
使用 `server_default=func.now()` 让数据库生成 created_at，避免应用服务器时间不一致。使用 `onupdate=func.now()` 在更新记录时自动刷新 updated_at。

### 四、categories 表

```python
# backend/app/models/category.py
from sqlalchemy import String, Text, Integer, DateTime, func
from sqlalchemy.orm import Mapped, mapped_column
from app.database import Base

class Category(Base):
    __tablename__ = "categories"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(100), unique=True, nullable=False)
    description: Mapped[str] = mapped_column(Text, nullable=True)
    sort_order: Mapped[int] = mapped_column(Integer, default=0)
    created_at: Mapped[DateTime] = mapped_column(DateTime, server_default=func.now())
```

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | Integer | 主键，自增 | 分类 ID |
| name | String(100) | 唯一，非空 | 分类名 |
| description | Text | 可空 | 分类描述 |
| sort_order | Integer | 默认 0 | 排序序号 |
| created_at | DateTime | 数据库默认 | 创建时间 |

### 五、problems 表

```python
# backend/app/models/problem.py
from sqlalchemy import String, Text, Integer, DateTime, func, ForeignKey
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.orm import Mapped, mapped_column
from app.database import Base

class Problem(Base):
    __tablename__ = "problems"

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    title: Mapped[str] = mapped_column(String(200), nullable=False)
    category_id: Mapped[int] = mapped_column(ForeignKey("categories.id"), nullable=False)
    description: Mapped[str] = mapped_column(Text, nullable=False)
    type: Mapped[str] = mapped_column(String(20), nullable=False)
    difficulty: Mapped[int] = mapped_column(Integer, nullable=False)
    tags: Mapped[list] = mapped_column(JSONB, default=list)
    answer: Mapped[str] = mapped_column(Text, nullable=True)
    explanation: Mapped[str] = mapped_column(Text, nullable=True)
    options: Mapped[list] = mapped_column(JSONB, nullable=True)
    blanks: Mapped[list] = mapped_column(JSONB, nullable=True)
    created_at: Mapped[DateTime] = mapped_column(DateTime, server_default=func.now())
    updated_at: Mapped[DateTime] = mapped_column(
        DateTime, server_default=func.now(), onupdate=func.now()
    )
```

### 十、通用性技术总结

#### 1、字段类型选择

| 场景 | 推荐类型 | 理由 |
|---|---|---|
| 短字符串 | String(n) | 可加长度限制，索引高效 |
| 长文本 | Text | 无长度限制 |
| 结构化数组/字典 | JSONB | 无需建表，支持索引 |
| 布尔标志 | Boolean | 语义清晰 |
| 时间戳 | DateTime + server_default | 数据库统一生成 |

#### 2、默认值的使用
- Python 端默认值 `default=X`：SQLAlchemy 在插入时使用，但数据库无默认约束
- 数据库端默认值 `server_default=func.now()`：建表时生成 `DEFAULT CURRENT_TIMESTAMP`
- 时间戳、不可变默认值推荐用 `server_default`
- 可变默认值（如 list）在 Python 端用 `default=list`

#### 3、为什么可变默认值要用 default=list

错误写法：
```python
tags: Mapped[list] = mapped_column(JSONB, default=[])
```
此时所有实例共享同一个列表对象，一个实例修改 tags 会影响其他实例。

正确写法：
```python
tags: Mapped[list] = mapped_column(JSONB, default=list)
```
`default=list` 是函数引用，每次调用生成新列表。

### 十二、注意事项

#### 1、类名大小写
- SQLAlchemy 的字段类型 `DateTime` 中 **T 必须大写**，误写为 `DataTime` 会报 ImportError。
- 类似的 `Boolean`、`Integer`、`String` 都是首字母大写。

#### 2、字段类型必须与语义一致
- `sort_order` 是整数排序字段，类型应为 `Integer`。
- 误写为 `DateTime` 会导致后续插入整数时类型不匹配。
- 一旦发现类型错误，需要重新生成迁移（`docker compose down -v` 重置数据库）。

#### 3、外键的写法
- `ForeignKey("categories.id")` 是字符串形式，`表名.列名` 全小写。
- 不要写成 `Category.id` 或 `categories.ID`。

#### 4、字段顺序无关
- 模型字段定义顺序不影响表结构，但建议按逻辑分组（主键、业务字段、时间戳）。

#### 5、中文注释乱码
- Windows 默认编码可能是 GBK。
- 保存 `.py` 文件时确保 VS Code 右下角显示 **UTF-8**。
- 若已经乱码，可点击编码 → Reopen with Encoding → UTF-8 → Save with Encoding → UTF-8。

#### 6、JSONB 与 JSON 的区别
- PostgreSQL 提供 `JSON` 和 `JSONB` 两种类型。
- `JSON` 存文本，保留格式；`JSONB` 存二进制，支持索引。
- 生产环境优先用 `JSONB`。

#### 7、默认值的坑
- `default=[]`、`default={}` 这类可变默认值会引发共享问题，**永远不要写**。
- 用 `default=list`、`default=dict` 替代。
