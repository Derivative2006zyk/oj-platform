# 第 45 天：插件包规范与动态加载机制

### 一、今日目标

- 定义 `.ojplugin` 插件包的核心文件 `manifest.json` 规范
- 修改基础设施，将外部插件目录挂载到 Docker 容器
- 改造 `entrypoint.sh` 支持自动安装外部插件的 Python 依赖
- 重写后端 `PluginRegistry`，支持从外部挂载目录动态扫描并加载插件
- 编写 `hello_world` 插件进行加载验证

### 二、核心实现

#### 1、插件目录规范
本地开发和用户环境中，外部插件分别存放在：
- 开发：`backend/plugins_installed/`
- 用户：`%APPDATA%\oj-platform\plugins_installed/`

一个标准的插件必须包含 `manifest.json` 和 `backend/__init__.py`。

#### 2、基础设施改造
- **数据卷挂载**：在 `docker-compose.yml` 的 `backend` 和 `worker` 服务中，增加 `./backend/plugins_installed:/app/plugins_installed` 的绑定挂载。
- **依赖自动安装**：修改 `backend/entrypoint.sh`。在启动 uvicorn 之前，遍历 `/app/plugins_installed` 目录，如果发现插件包含 `requirements.txt`，则自动执行 `pip install`。

#### 3、动态加载引擎
- 重构 `backend/app/core/plugin_registry.py`。
- 新增 `discover_external` 方法：遍历外部目录，使用 `importlib.util.spec_from_file_location` 动态加载模块。
- 在 `main.py` 中，除了原有的 `_registry.discover("app.plugins")`，新增调用 `_registry.discover_external("/app/plugins_installed")`。

### 三、踩坑记录

#### 1、外部插件加载成功但实例列表为空
**现象**：日志显示 `Found external plugin: hello_world`，但紧接着打印的 `plugins: []` 却什么都没有，连内置插件也消失了。
**原因**：重写 `plugin_registry.py` 时，`@register_plugin` 装饰器只标记了类，没有将其加入全局列表，导致后续的 `_build_instances` 找不到任何类。
**解决**：使用全局变量 `_plugin_classes` 来收集所有被装饰的类，并在 `_build_instances` 中遍历实例化。
