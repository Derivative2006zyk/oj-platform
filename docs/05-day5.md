### 一、鉴权机制

#### 1、实现
```python
# backend/app/core/security.py
from fastapi import Header, HTTPException
from app.core.config import settings

async def verify_admin_key(x_admin_key: str = Header(None)):
    if x_admin_key != settings.ADMIN_KEY:
        raise HTTPException(status_code=403, detail="管理员密钥错误")
    return x_admin_key
```

#### 2、在路由中使用
```python
@router.post("/admin/problems", status_code=201)
async def create_problem(
    data: ProblemCreate,
    db: AsyncSession = Depends(get_db),
    _: str = Depends(verify_admin_key),
):
    ...
```

`Depends(verify_admin_key)` 会在路由函数执行前先执行 verify_admin_key，若抛异常则路由不执行。

#### 3、鉴权的通用模式

| 模式 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| Header 密钥 | 内部管理系统 | 简单 | 无法精细授权 |
| JWT | 多用户系统 | 无状态，可携带信息 | 需要签名验证 |
| Session | 传统 Web | 服务端可控 | 需要会话存储 |
| OAuth | 第三方登录 | 标准化 | 实现复杂 |

### 二、创建题目

```python
async def create_problem(db, data):
    problem = Problem(
        title=data.title, category_id=data.category_id,
        description=data.description, type=data.type,
        difficulty=data.difficulty, tags=data.tags,
        answer=data.answer, explanation=data.explanation,
        options=data.options, blanks=data.blanks,
    )
    db.add(problem)
    await db.flush()

    if data.type == "algorithm":
        for tc in data.test_cases:
            db.add(TestCase(
                problem_id=problem.id, input_data=tc.input_data,
                expected_output=tc.expected_output, is_example=tc.is_example,
            ))

    if data.type == "research":
        for sp in data.subprojects:
            db.add(ResearchSubproject(
                problem_id=problem.id, title=sp.title,
                description=sp.description, hint=sp.hint,
                reference_links=sp.reference_links,
                answer_guide=sp.answer_guide, sort_order=sp.sort_order,
            ))

    await db.commit()
    await db.refresh(problem)
    return problem
```

#### 关键技术点

| 技术点 | 说明 |
|---|---|
| `db.add(obj)` | 将对象加入会话，但未执行 SQL |
| `await db.flush()` | 立即发送 SQL，获得自增 ID，但未提交事务 |
| `await db.commit()` | 提交事务 |
| `await db.refresh(obj)` | 从数据库重新加载对象属性 |

#### flush 与 commit 的差异
flush 生成 SQL 但不持久化，可以回滚；commit 持久化事务。在需要引用自增 ID 插入关联表时，flush 是必需的。

### 三、更新题目

```python
async def update_problem(db, problem_id, data):
    problem = await db.get(Problem, problem_id)
    if not problem:
        return None

    update_data = data.model_dump(exclude_unset=True)
    test_cases_data = update_data.pop("test_cases", None)
    subprojects_data = update_data.pop("subprojects", None)

    for field, value in update_data.items():
        setattr(problem, field, value)

    if test_cases_data is not None:
        await db.execute(delete(TestCase).where(TestCase.problem_id == problem_id))
        for tc in test_cases_data:
            db.add(TestCase(
                problem_id=problem_id, input_data=tc["input_data"],
                expected_output=tc["expected_output"],
                is_example=tc.get("is_example", True),
            ))

    if subprojects_data is not None:
        await db.execute(delete(ResearchSubproject).where(ResearchSubproject.problem_id == problem_id))
        for sp in subprojects_data:
            db.add(ResearchSubproject(
                problem_id=problem_id, title=sp["title"],
                description=sp["description"], hint=sp.get("hint"),
                reference_links=sp.get("reference_links", []),
                answer_guide=sp.get("answer_guide"),
                sort_order=sp.get("sort_order", 0),
            ))

    await db.commit()
    await db.refresh(problem)
    return problem
```

#### 1、exclude_unset 的原理
`model_dump(exclude_unset=True)` 只返回请求体中显式提供的字段。未提供的字段保留数据库原值，实现部分更新。

| 参数 | 行为 |
|---|---|
| `exclude_unset=True` | 只返回显式设置的字段 |
| `exclude_none=True` | 过滤值为 None 的字段 |
| `exclude_defaults=True` | 过滤等于默认值的字段 |

#### 2、子表替换策略
更新时对 test_cases 和 subprojects 采用"先删后插"策略：如果请求中提供了对应字段，先删除该题目所有关联行，再插入新的。优点是逻辑简单，避免逐条比对。

### 四、删除题目

```python
async def delete_problem(db, problem_id):
    problem = await db.get(Problem, problem_id)
    if not problem:
        return False
    await db.delete(problem)
    await db.commit()
    return True
```

删除操作依赖数据库外键的 `ondelete="CASCADE"`，自动级联删除 test_cases、research_subprojects 和 images。

### 六、HTTP 状态码语义

| 状态码 | 含义 | 使用场景 |
|---|---|---|
| 200 | 成功 | 一般 GET/PUT/DELETE |
| 201 | 已创建 | POST 创建资源 |
| 400 | 请求错误 | 参数不合法 |
| 403 | 禁止访问 | 鉴权失败 |
| 404 | 资源不存在 | 目标 ID 不存在 |
| 422 | 实体无法处理 | Pydantic 校验失败 |
| 500 | 服务器错误 | 未捕获异常 |

### 七、注意事项

#### 1、鉴权 Header 名称
- FastAPI 的 `Header(None)` 参数 `x_admin_key` 会自动映射为请求头 `x-admin-key`（下划线转连字符，大小写不敏感）。
- Swagger 中填 Headers 时用 `x-admin-key`。

#### 2、管理员密钥的存储
- 默认密钥 `admin-key-change-me` 仅用于开发。
- 生产环境必须通过环境变量 `ADMIN_KEY` 覆盖。
- 不要把真实密钥写入源码或版本库。

#### 3、db.flush 与 db.commit 的选择
- 需要立即拿到自增 ID（用于插入子表）：必须 `flush`。
- 只操作主表，不需要 ID：可省略 `flush`。
- 所有操作完成后必须 `commit`，否则事务未提交。

#### 4、更新时 exclude_unset 的必要性
- 不加 `exclude_unset=True` 时，未提供的字段会被设置为 `None`，导致数据被意外清空。
- 例如只更新 `title` 时，`category_id` 会被更新为 `None`，外键约束会报错。

#### 5、pop 后必须判 None
- `update_data.pop("test_cases", None)` 若请求中未提供 test_cases，返回 None。
- 若直接遍历 None 会报 `TypeError: 'NoneType' object is not iterable`。
- 判断 `is not None` 才能执行替换逻辑。

#### 6、子表替换的事务性
- 先 `delete` 再 `add` 在同一个事务内，中间若出错会整体回滚。
- 不要在替换中间 `commit`，否则旧数据已删、新数据未插，造成数据丢失。

#### 7、Pydantic 校验失败时返回 422
- 422 不是服务端错误，是客户端请求格式不正确。
- 响应体会明确指出哪个字段、什么原因。

#### 8、中文注释乱码
- 与前几天一致，必须用 UTF-8 保存。
- 建议用英文注释，避免跨平台问题。
