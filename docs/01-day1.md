### 二、分层架构原则

```
路由层 (api.py)   ← HTTP 请求处理、参数校验
    ↓
服务层 (service.py) ← 业务逻辑、数据库操作
    ↓
模型层 (models)    ← 数据结构定义
```

原则：
- 路由层不直接操作数据库，只调用服务层
- 服务层不处理 HTTP 细节，只处理业务
- 模型层不感知 HTTP 与业务

### 四、配置类

#### 1、实现
```python
# backend/app/core/config.py
from pydantic_settings import BaseSettings
import os

class Settings(BaseSettings):
    DATABASE_URL: str = "postgresql+asyncpg://oj:oj_password@localhost:5432/oj_platform"
    ADMIN_KEY: str = "admin-key-change-me"
    UPLOAD_DIR: str = os.path.join(
        os.path.dirname(os.path.dirname(os.path.dirname(__file__))), "uploads"
    )
    MAX_IMAGE_SIZE: int = 5 * 1024 * 1024

    class Config:
        env_file = ".env"

settings = Settings()
os.makedirs(settings.UPLOAD_DIR, exist_ok=True)
```

#### 2、加载顺序
```
环境变量 > .env 文件 > 默认值
```

| 层次 | 来源 | 使用场景 |
|---|---|---|
| 环境变量 | OS 或 Docker | 生产部署 |
| .env 文件 | 项目根目录 | 本地开发 |
| 默认值 | 类定义 | 首次启动 |

#### 3、DATABASE_URL 格式
```
postgresql+asyncpg://用户名:密码@主机:端口/数据库名
```

### 五、FastAPI 入口

#### 1、初始版本
```python
# backend/app/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(title="OJ Platform", version="0.1.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.get("/health")
async def health():
    return {"status": "ok"}
```

#### 2、CORS 中间件参数

| 参数 | 作用 |
|---|---|
| allow_origins | 允许的源，生产环境应指定具体域名 |
| allow_methods | 允许的 HTTP 方法 |
| allow_headers | 允许的请求头（如 X-Admin-Key） |

#### 3、/health 接口的意义
应用的"心跳检测"接口。负载均衡器、Kubernetes、监控系统通过定期访问该接口判断服务是否健康。

### 六、Docker Compose 数据库编排

#### 1、编排文件
```yaml
services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: oj
      POSTGRES_PASSWORD: oj_password
      POSTGRES_DB: oj_platform
    ports:
      - "5432:5432"
    volumes:
      - pg_data:/var/lib/postgresql/data

volumes:
  pg_data:
```

#### 2、字段说明

| 字段 | 说明 |
|---|---|
| image | postgres:15-alpine 镜像，体积小 |
| environment | 初始化时创建用户/密码/库 |
| ports | 端口映射，主机 5432 → 容器 5432 |
| volumes | 命名卷，持久化数据 |

#### 3、数据持久化原理
volumes 定义命名卷 `pg_data`，实际存储在 Docker 引擎管理的目录中。容器销毁后数据仍然保留，除非显式执行 `docker compose down -v`。

#### 4、常用命令

| 命令 | 效果 |
|---|---|
| `docker compose up -d` | 后台启动容器 |
| `docker compose down` | 停止并删除容器，保留卷 |
| `docker compose down -v` | 停止并删除容器和卷（数据丢失） |
| `docker ps` | 查看运行中的容器 |
| `docker logs 容器名` | 查看容器日志 |

### 八、启动流程

```
cd backend
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

cd E:\github_project\oj-platform
docker compose up -d

cd backend
uvicorn app.main:app --reload --port 8000
```

`--reload` 的作用：uvicorn 监听源码变更。保存代码后自动重启服务。原理是 uvicorn 启动一个 reloader 进程监测 .py 文件时间戳，变更时重启 worker 进程。

### 九、注意事项

#### 1、路径必须切换正确
- 安装依赖时必须在 `backend` 目录下。
- 启动数据库必须在项目根目录 `E:\github_project\oj-platform`。
- 启动后端必须在 `backend` 目录下。
- 路径错误会报 `ModuleNotFoundError` 或找不到 `docker-compose.yml`。

#### 2、容器命名
- 容器名默认为 `项目目录名-服务名-序号`，本项目为 `oj-platform-postgres-1`。
- 若项目目录改名，容器名也会改变，后续命令需相应调整。

#### 3、端口冲突
- 若 5432 端口已被本机 PostgreSQL 占用，Docker 启动会失败。
- 排查方式：`netstat -ano | findstr :5432`。
- 解决：修改 `docker-compose.yml` 中端口映射为 `5433:5432`，同时更新 `DATABASE_URL`。

#### 4、uvicorn 的 --reload
- 生产环境不要使用 `--reload`，会消耗额外资源监测文件。
- 开发环境使用 `--reload`，避免每次修改代码都要手动重启。

#### 5、文件编码
- 所有 `.py` 文件保存为 **UTF-8**。
- 中文注释若显示为乱码，说明文件被保存为 GBK，需在 VS Code 右下角切换编码。
