# 第6天：图片上传 API

### 一、完整流程

```
客户端 POST multipart/form-data
    ↓
FastAPI 解析 UploadFile
    ↓
校验类型 → 校验大小 → 校验有效性
    ↓
可选：校验关联题目的题型
    ↓
生成唯一文件名，按年月分目录
    ↓
写入磁盘
    ↓
插入 images 表
    ↓
返回 {id, url}
```

### 二、核心实现

```python
# backend/app/plugins/problem_plugin/image_api.py
import uuid, os
from datetime import datetime
from fastapi import APIRouter, Depends, HTTPException, UploadFile, File, Form
from fastapi.responses import FileResponse
from PIL import Image as PILImage
from app.database import async_session
from app.models.problem import Problem
from app.models.image import Image
from app.core.config import settings
from app.core.security import verify_admin_key

router = APIRouter(prefix="/api", tags=["images"])

ALLOWED_TYPES = ["image/png", "image/jpeg", "image/webp"]
BLOCKED_PROBLEM_TYPES = ["choice", "fill_blank"]

async def get_db():
    async with async_session() as session:
        yield session

@router.post("/admin/images", status_code=201)
async def upload_image(
    file: UploadFile = File(...),
    problem_id: int = Form(None),
    db: AsyncSession = Depends(get_db),
    _: str = Depends(verify_admin_key),
):
    if file.content_type not in ALLOWED_TYPES:
        raise HTTPException(status_code=400, detail="仅支持PNG/JPEG/WebP格式")

    content = await file.read()
    if len(content) > settings.MAX_IMAGE_SIZE:
        raise HTTPException(status_code=400, detail="图片大小不能超过5MB")

    try:
        img = PILImage.open(file.file)
        img.verify()
    except Exception:
        raise HTTPException(status_code=400, detail="无效的图片文件")
    finally:
        file.file.seek(0)

    if problem_id is not None:
        problem = await db.get(Problem, problem_id)
        if not problem:
            raise HTTPException(status_code=404, detail="题目不存在")
        if problem.type in BLOCKED_PROBLEM_TYPES:
            raise HTTPException(status_code=400, detail="选择题和填空题不支持图片")

    ext = os.path.splitext(file.filename)[1].lower()
    unique_name = f"{uuid.uuid4().hex}{ext}"
    date_dir = datetime.now().strftime("%Y/%m")
    upload_dir = os.path.join(settings.UPLOAD_DIR, date_dir)
    os.makedirs(upload_dir, exist_ok=True)
    file_path = os.path.join(upload_dir, unique_name)

    with open(file_path, "wb") as f:
        f.write(content)

    image = Image(
        problem_id=problem_id, file_name=file.filename,
        file_path=file_path, file_size=len(content),
        mime_type=file.content_type, upload_by="admin",
    )
    db.add(image)
    await db.commit()
    await db.refresh(image)

    return {"id": image.id, "url": f"/api/images/{image.id}"}

@router.get("/images/{image_id}")
async def get_image(image_id: int, db: AsyncSession = Depends(get_db)):
    image = await db.get(Image, image_id)
    if not image:
        raise HTTPException(status_code=404, detail="图片不存在")
    if not os.path.exists(image.file_path):
        raise HTTPException(status_code=404, detail="图片文件已丢失")
    return FileResponse(image.file_path, media_type=image.mime_type)
```

### 三、关键技术点分析

#### 1、multipart/form-data 处理
FastAPI 中，`File(...)` 接收文件字段，`Form(...)` 接收普通表单字段。UploadFile 提供以下属性：

| 属性 | 说明 |
|---|---|
| filename | 原始文件名 |
| content_type | MIME 类型 |
| file | 底层文件对象 |

#### 2、三层校验

| 层级 | 检查项 | 失败处理 |
|---|---|---|
| 类型 | content_type 是否在允许列表 | 400 |
| 大小 | 字节数是否超限 | 400 |
| 有效性 | Pillow 能否打开并 verify | 400 |

#### 3、Pillow 的 verify 与指针重置
Pillow 的 `Image.open` 读取文件头判断类型，`img.verify()` 进一步验证完整性。但验证会消耗文件流，需要 `file.file.seek(0)` 重置指针。若在保存前不重置，写入磁盘的将是空文件。

#### 4、唯一文件名生成
`uuid.uuid4().hex` 生成 32 位十六进制字符串，全局唯一。按年/月分目录避免单目录文件过多，提高文件系统性能。

#### 5、FileResponse 的实现
Starlette 提供的响应类型，用于高效传输文件。自动处理 Content-Length、Content-Type 和 Range 请求。相比读取文件后返回 bytes，FileResponse 使用 sendfile 系统调用，性能更优。

### 四、题型限制的通用性设计

#### 1、为什么限制
选择题与填空题的选项/空位结构已经在 JSONB 字段中定义，不需要图片。限制图片是为了保持数据结构清晰。

#### 2、实现方式
定义 `BLOCKED_PROBLEM_TYPES = ["choice", "fill_blank"]`，在关联题目时检查 type 是否在此列表中。

### 五、文件存储与元数据分离

| 方案 | 优点 | 缺点 |
|---|---|---|
| 文件存磁盘，DB 存路径 | 数据库轻量，文件可直接访问 | 需保证文件系统与数据库一致性 |
| 文件存数据库（BLOB） | 事务原子性 | 数据库膨胀，查询慢 |
| 对象存储（S3 等） | 可扩展，解耦 | 需要额外服务 |

### 六、安全考虑

| 风险 | 防御 |
|---|---|
| 上传非图片文件 | content_type + Pillow 双校验 |
| 上传超大文件 | 大小限制 |
| 文件名冲突 | UUID 重命名 |
| 路径穿越攻击 | 不接受用户提供的路径，只接受文件名 |
| MIME 欺骗 | Pillow 会真实解析文件头 |

### 七、注意事项

#### 1、路由路径必须用复数
- 上传路由：`/admin/images`（复数）
- 访问路由：`/images/{image_id}`（复数）
- 若写成单数 `/image`，前端访问会 404。

#### 2、三个拼写陷阱
- `include_router` 不是 `inculde_router`
- `content_type` 不是 `content_typed`
- `settings` 不是 `setting`
- 这三处是本项目踩过最多的拼写坑。

#### 3、Swagger 的 Send empty value
- 若勾选 `Send empty value`，`problem_id` 会发送为空字符串 `""`。
- FastAPI 尝试解析为空整数，返回 422 `int_parsing`。
- 解决：取消勾选，直接不填即可。

#### 4、上传后访问 404 的常见原因
- 路由单复数不一致（上传是 `/images`，访问是 `/image`）。
- 数据库 `file_path` 记录错误（如保存为相对路径，读取时找不到）。
- 文件被手动删除或移动到其他目录。

#### 5、文件指针重置的必要性
- `await file.read()` 读取后指针在末尾。
- `PILImage.open(file.file)` 又从指针位置开始读。
- 若不 seek(0)，Pillow 会打开空文件。

#### 6、verify 后再打开
- `img.verify()` 会消耗图片对象，之后不能再用 `img` 做其他操作。
- 若需要获取尺寸等元信息，应在 verify 之前读取或重新打开。

#### 7、Content-Type 的信任度
- 客户端可伪造 `content_type`。
- 不能仅凭 content_type 判定文件类型。
- Pillow 的 `verify()` 是二次保险。

#### 8、时间目录的时区
- `datetime.now()` 使用服务器本地时间。
- 若希望统一用 UTC，改为 `datetime.utcnow()`。

#### 9、uploads 目录的权限
- Windows 下通常无问题。
- Linux 部署时确保运行 uvicorn 的用户对 `uploads/` 有写权限。

#### 10、数据库一致性
- 若文件写入成功但数据库插入失败，磁盘会残留孤儿文件。
- 若数据库插入成功但文件写入失败，访问时会返回"文件已丢失"。
- 生产环境可加定时清理任务。
