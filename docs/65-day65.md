# 第 65 天：数据结构升级与 AI 录题链路重构

### 一、今日目标

在完成 AI 助教深度嵌入（Day 64）后，我们发现“录题”这一核心业务存在两个痛点：
1. **分类粒度不够**：现有的 `分类 -> 题库(Bank) -> 题目(Problem)` 难以满足真实场景（一张试卷包含多道题），且无法批量将多道题导入同一个试卷。
2. **AI OCR 的不稳定性**：大模型虽然能识别整张试卷，但返回的 LaTeX 反斜杠极易被 Python 的 `json.loads` 当做特殊控制字符吃掉，且经常将同一题的小问拆开，或者输出非法的 KaTeX 极限语法导致前端渲染崩溃。

今日的核心任务是：**引入“试卷（Paper）”概念，形成 分组(Bank) -> 试卷(Paper) -> 题目(Problem) 的三级层级；同时，在前后端为 AI 生成的数据打造“防弹衣”，彻底解决公式乱码与排版崩溃。**

### 二、核心实现

#### 1、架构升级：三级数据模型重构
在后端 `models` 中新增 `Paper` 表，作为 `Bank` 的子级；在 `Problem` 表中挂载 `paper_id` 外键（允许为空，兼容旧数据），并完成数据库迁移。

```python
# backend/app/models/paper.py
class Paper(Base):
    __tablename__ = "papers"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(200))
    bank_id: Mapped[int] = mapped_column(ForeignKey("banks.id", ondelete="CASCADE"))

# backend/app/models/problem.py
class Problem(Base):
    # ...
    paper_id: Mapped[int] = mapped_column(ForeignKey("papers.id", ondelete="SET NULL"), nullable=True)
```

#### 2、前端交互升级与视图改造
*   **题库列表页 (`ProblemList.vue`)**：重构原有分组视图，实现 `Bank -> Paper -> Problem` 的三级折叠树。在筛选区新增「试卷」下拉框，支持按试卷过滤。
*   **题目编辑页 (`ProblemEdit.vue`)**：在题库选择下方新增「所属试卷」下拉框，并监听 `bank_id` 变化自动请求对应试卷列表。
*   **AI 识别弹窗 (`OcrUploader.vue`)**：在预览步骤新增题库与试卷双下拉框，批量导入时自动将 `paper_id` 注入给所有勾选的题目。

#### 3、AI OCR 数据清洗与渲染防弹衣
面对大模型返回的不稳定 Markdown/LaTeX 格式，前后端增加了强力的正则清洗：
*   **拯救反斜杠**：Python 解析 JSON 时，`\frac` 会被识别为换页符 `\x0c`。后端在 `json.loads` 前强行将常用命令补全为 `\\frac`，并在返回前替换回控制字符。
*   **修复 KaTeX 语法**：清理不规范的绝对值（`\vert`、`\lvert`）为纯竖线 `|`；通过正则拦截 `\lim_\limits` 等非法写法，统一规范化为标准的 `\lim\limits_{...}`。
*   **强制合并小问**：利用正则检测 `(1)`、`(2)` 等题号，若识别为子小问，强行拼接到上一题的 `description` 中。

### 三、踩坑记录

#### 1、FastAPI 路由前缀拼接导致 404
**现象**：在 `admin_api.py` 中新增 `/batch` 批量导入接口后，前端请求报 404。
**原因**：该文件的 `router` 原本带有 `prefix="/api/admin/plugins"`，再写 `@router.post("/admin/problems/batch")` 会导致路径拼接错误。
**解决**：将该文件的 `router` 前缀置空 `prefix=""`，并在所有路由上手写绝对路径。

#### 2、控制字符导致 JSON 解析崩溃与渲染异常
**现象**：大模型成功识别了多道题，但后端返回 500，或者前端报错 `Missing open brace for subscript`。
**原因**：
1. 模型输出了单反斜杠（如 `\vert`），被 `json.loads` 解析成了不可见控制字符 `\x0b`。
2. 之前写的清洗正则生成了非法的 KaTeX 语法 `\lim_\limits`（下划线位置错误）。
**解决**：后端增加 `clean_latex` 函数恢复控制字符，并通过正则 `re.sub(r'\\lim_?\s*(\\limits)?_?\s*\{', r'\\lim\\limits_{', text)` 统一极限语法。

#### 3、Docker 容器内 DNS 解析失效
**现象**：前端点击识别，后端报 500 错误 `[Errno -5] No address associated with hostname`。
**原因**：Docker 容器重启后，内部默认的 DNS 代理失效，无法解析智谱 API 的域名。
**解决**：在 `httpx.AsyncClient` 中强制加入 `trust_env=False` 绕过内部代理，并在 `docker-compose.yml` 中为 backend 服务配置公共 DNS（如 `8.8.8.8`）。
