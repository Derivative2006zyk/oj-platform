### 二、核心实现

#### 1、上下文握手改为长窗口重试

原实现只重试 6 次、间隔 700ms，在 Tauri 冷启动、插件页加载较慢时会错过父窗口挂载监听器的时机，导致 `state.token` 始终为空，页面停留在「正在读取模型配置…」。

子页面侧改为 40 次、间隔 500ms（覆盖约 20 秒）：

```js
function requestContext() {
  if (window.parent === window) return

  function send() {
    if (state.contextReceived) return
    window.parent.postMessage({ type: 'oj:plugin-ready' }, '*')
    state.contextAttempts += 1
    if (state.contextAttempts < 40 && !state.contextReceived) {
      window.setTimeout(send, 500)
    }
  }

  send()
}
```

父窗口侧在 iframe 加载后**连续推送多次**，而不是只推一次：

```js
let contextTimers: number[] = []

function scheduleContextPushes() {
  contextTimers.forEach(t => window.clearTimeout(t))
  contextTimers = [0, 120, 400, 900, 1600, 2500].map(delay =>
    window.setTimeout(postContext, delay)
  )
}
```

两端同时加强，任何一侧响应慢一些，也都能完成握手。

#### 2、iframe 缓存规避

`iframeUrl` 增加一次性时间戳参数，路由切换时刷新：

```ts
const cacheBuster = ref(Date.now())

const iframeUrl = computed(() => {
  if (!pluginName.value) return ''
  const base = getBackendUrl()
  const name = encodeURIComponent(pluginName.value)
  return `${base || ''}/plugins_static/${name}/frontend/index.html?v=${cacheBuster.value}`
})

watch(() => route.params.name, () => {
  loading.value = true
  cacheBuster.value = Date.now()
})
```

### 三、踩坑记录

#### 1、卸载插件后重装失败

**现象**：设置页卸载 `llm_ocr_plugin` 后点击安装，报 `Plugin class for 'llm_ocr_plugin' not found after reload`，反复重试均失败。
**原因**：卸载执行 `shutil.rmtree(target_dir)` 删除目录，但 `discover_external` 用 `sys.modules` 判断插件是否已加载：

```python
mod_name = f"ext_plugin_{plugin_name}"
if mod_name in sys.modules: continue
```

模块名仍在缓存中，重装时该插件被直接跳过，`_plugins` 里没有它，于是抛异常。
**解决**：删除目录后**必须重启后端**清空 `sys.modules` 再安装；或直接用开发源目录覆盖式重建，跳过市场安装流程。

#### 2、启动器探测端口后跳过资源解压

**现象**：安装新版 MSI 后，`%APPDATA%\oj-platform` 下的插件页仍是旧占位页。
**原因**：`ensure_backend_ready` 探测到 8000 端口已有后端在跑就直接返回，不执行资源解压。
**解决**：打包验证前统一 `docker compose down`，确认 `netstat -ano | findstr :8000` 无输出后再启动桌面端。

#### 3、cmd 下中文匹配失效导致误判

**现象**：`findstr /c:"AI 拍照录题" out.html` 无输出，一度怀疑后端返回旧文件。
**原因**：cmd 控制台默认 GBK 编码，文件是 UTF-8，中文匹配必然失败。
**解决**：改用 ASCII 关键字（`contextAttempts`、`oj:plugin-ready`）或直接看 `dir` 字节数判断。

#### 4、配置指向了不支持视觉的模型

**现象**：识别报 `[Errno -5] No address associated with hostname`，插件页停留在「检测中」。
**原因**：`current_profile` 指向 DeepSeek 配置（`deepseek-flash`），该模型不支持 `image_url` 入参；同时在命令行拼接多行命令导致出现多余字符。
**解决**：把 `current_profile` 切到智谱视觉模型，并确认 `base_url` 为 `https://open.bigmodel.cn/api/paas/v4`、模型名称为平台实际支持的视觉模型 ID。

#### 5、`timeout` 与 `ping` 在 cmd 中的可用性

**现象**：`timeout /t 20 >nul` 报 `invalid number '/t'`。
**原因**：conda 环境的 PATH 中存在其他名为 `timeout` 的可执行文件，遮蔽了系统 `timeout.exe`。
**解决**：改用 `ping -n 21 127.0.0.1 >nul` 等待；若被 `^C` 中断也不影响后续 `curl` 判断。
