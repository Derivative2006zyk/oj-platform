### 二、填空题判题器

`judge_fill_blank(answer_data, blanks)`：

- answer_data：`{"blanks": ["3", "4"]}`
- blanks 来自 `problems.blanks`
- match_rule 支持 `exact`、`ignore_case`
- 每个空正确则 passed_cases + 1
- 全对 AC，否则 WA
- runtime_ms 固定 0

### 三、判题通道

与选择题一致：同步判题，不入 arq、不走 Docker。

```python
if sub.submission_kind == "code":
    await enqueue("judge_submit", submission_id=sub.id)
else:
    await service.judge_inline(db, sub)
```

`judge_inline` 分支：

- `choice` → `judge_choice`
- `fill_blank` → `judge_fill_blank`
- `proof` → 状态 `SUBMITTED`，不判题

### 四、证明题提交

需求：支持文字 + 图片，不自动判题（判题留待 0.3 或 AI 接口层）。

数据：`submission_kind = "proof"`，`answer_data` 结构：

```json
{
  "text": "证明过程...",
  "images": [123, 124]
}
```

状态：提交后 `status = "SUBMITTED"`。

- 存盘到 `uploads/submissions/`
- 写 `images` 表，`problem_id` 为 NULL

### 七、草稿持久化

场景：提交后需要对照答案，输入内容不能丢。

方案：按 `problem_id` 存 localStorage，key 为 `oj_draft_{id}`。

- 输入变化 debounce 400ms 写入
- `loadProblem` 时读回
- 组件卸载立即保存
- 面板右上角"清空"按钮清除

覆盖范围：算法题、选择题、填空题、证明题。

### 八、踩坑记录

#### 1、`_infer_submission_kind` 双份

**现象**：证明题提交返回 422 `code is required for code submissions`。

**原因**：`_infer_submission_kind` 函数在 `schemas/submission.py` 和 `service.py` 中各有一份，只改了一处。

**解决**：两处都要加 `proof` 分支。这是当前架构冗余，0.3 可合并到一个工具模块。

#### 2、Redis 未启动

**现象**：pytest 全部 ERROR，`ConnectionRefusedError: Error 22 connecting to localhost:6379`。

**原因**：Redis 容器未运行，`flush_redis` fixture 失败。

**解决**：`docker compose up -d redis`。

#### 3、后端容器重启循环

**现象**：`docker compose ps` 显示 `Restarting`。

**原因**：Postgres 重启时还没就绪，后端连接失败崩溃，进入重启循环。

**解决**：等 Postgres 变 `healthy` 后，后端会自动恢复。日志尾部会显示 `Uvicorn running`。

#### 4、schemas 文件覆盖不全

**现象**：`ImportError: cannot import name 'SubmissionDetail'`。

**原因**：替换 `schemas/submission.py` 时只保留了 `SubmissionCreate`，另外两个类被删掉。

**解决**：三个类必须同时存在。

#### 5、草稿与提交内容

需求：提交后保留输入，便于对照答案。

方案：localStorage 按 problem_id 隔离，debounce 写入。
