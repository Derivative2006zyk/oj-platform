# 第 53 天：插件启用/禁用与配置持久化

### 一、今日目标
- 基于 `plugin_configs` 表实现插件启用状态的持久化存储。
- 重构 `PluginRegistry`，启动时根据数据库状态跳过禁用插件，并过滤其路由。
- 后端 API `PUT /api/admin/plugins/{name}/enable` 和 `/disable` 接入数据库。
- 前端实现插件启用/禁用的 UI 切换，并将状态同步到顶部导航栏。
- 修复外部插件 `name` 字段与目录名不一致导致 404 的隐患。

### 二、核心实现

#### 1、配置存储层（plugin_config_store）
- 沿用 0.2 时期建好的 `plugin_configs` 表（`plugin_name` 唯一、`enabled` 布尔、`config` JSONB）。
- 新增 `ensure_config` 逻辑：安装插件时确保记录存在；启用/禁用时通过 `set_enabled` 更新字段。

#### 2、PluginRegistry 状态感知加载
- **load_all**：启动时一次性查出所有插件配置，禁用的插件直接跳过 `plugin.on_load()`，并在实例上动态打上 `_enabled = False` 标记。
- **collect_routers**：只收集 `_enabled = True` 的插件路由，确保被禁用的插件不会挂载到 FastAPI 应用上（重启后生效）。
- **install_plugin**：安装时调用 `ensure_config(name, default_enabled=True)`，保证新装的插件默认开启。

#### 3、强一致性：目录名覆盖类名
- 历史遗留的 `hello_world` 插件，代码内 `name = "hello_world_ext"`，导致前端传目录名去禁用时，后端内存字典找不到。
- 修复方案：在 `discover_external` 动态导入外部插件类后，判断类的 `name` 是否与所在文件夹名一致。如果不一致，强行覆盖 `cls.name = folder_name`。从根源上杜绝第三方插件乱起名字导致的冲突。

#### 4、API 层接口
- 改造 `admin_api.py`：`enable` 和 `disable` 接口不再抛出 404 异常，而是**直接写数据库**。
- 如果内存里有这个插件实例，顺便更新内存状态；如果没有（比如没加载成功），依赖用户重启后生效。

#### 5、前端双联动（Settings + NavBar）
- **Settings.vue**：已安装插件卡片增加「启用/禁用」按钮。禁用状态下卡片透明度降低，按钮文案切换为「启用」。
- **NavBar.vue**：顶部动态菜单的 `v-for` 循环增加 `v-if="p.enabled !== false"` 判断。一旦用户在设置页禁用插件，跳回主页后菜单即刻消失。

### 三、踩坑记录

#### 1、`Plugin not found` 的 404 报错
**现象**：在设置页点击禁用 `Hello World` 插件，前端弹窗提示“操作失败：Plugin not found”。
**原因**：示例插件的 `manifest.json` 写的名字是 `hello_world`，但代码里写的是 `hello_world_ext`。前端请求 `PUT /api/admin/plugins/hello_world/disable`，后端去 `_plugins` 字典查不到，抛了异常。
**解决**：移除 API 里的 404 拦截（直接写库），并在加载外部插件时强行将类名覆盖为文件夹名。

#### 2、导航栏未过滤禁用状态
**现象**：后端已成功禁用插件，设置页也变灰了，但顶部导航栏的「示例页」依然存在。
**原因**：忘记在 `NavBar.vue` 渲染时过滤 `enabled` 状态。
**解决**：在 `NavBar.vue` 的 `v-for` 循环里加入 `v-if="p.enabled !== false"` 判断。
