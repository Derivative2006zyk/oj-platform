# 第 57 天：多端数据同步（全局 WebSocket 实时广播）

### 一、今日目标
- 基于 0.2 版本已有的 WebSocket 与 Redis EventBus 基础设施，扩展出全局广播能力。
- 实现题库列表页的实时同步：任意一台设备新建、修改或删除题目，其他在线设备无需手动刷新即可自动更新列表。

### 二、核心实现

#### 1、后端：扩展 WSManager 支持全局广播
- 在 `ws_manager.py` 中新增全局连接池 `_global_connections`。
- 提供 `connect_global`、`disconnect_global` 以及 `broadcast` 方法，用于向所有在线客户端群发消息（与原有的按 user_id 定向推送分离）。

#### 2、后端：WebSocket 路由与事件订阅
- 在 `problem_plugin/api.py` 中新增 `/ws/global` 端点（注意由于 router 已有 `/api` 前缀，此处不能重复添加），用于接收并保持前端的全局连接。
- 在 `problem_plugin/__init__.py` 中，利用 `EventBus` 订阅 `problem.created`、`problem.updated` 和 `problem.deleted` 事件。
- 当后端发生题库 CRUD 操作并发布事件后，插件监听到事件，立即通过 `WSManager.broadcast` 向前端推送 `{"type": "problem.created", "data": {...}}`。

#### 3、前端：WebSocket 封装与静默刷新
- 在 `utils/ws.ts` 中新增 `openGlobalWS` 函数，用于建立全局长连接。
- 在 `ProblemList.vue` 中，于 `onMounted` 时建立连接，并在 `onUnmounted` 时安全关闭。
- 当监听到 `problem.*` 事件时，静默调用 `loadProblems()` 和 `loadBanks()`（不显示 Loading 遮罩），实现无感刷新。

### 三、踩坑记录

#### 1、路由前缀重复导致 404
**现象**：WebSocket 连接 `/api/ws/global` 一直失败。
**原因**：`api.py` 中的 `router = APIRouter(prefix="/api")` 已经包含了前缀，但代码里写成了 `@router.websocket("/api/ws/global")`，最终路径变成了 `/api/api/ws/global`。
**解决**：将装饰器改为 `@router.websocket("/ws/global")`。

#### 2、Vite 代理未开启 WS 导致握手失败
**现象**：浏览器 F12 报错 `WebSocket connection to 'ws://localhost:5173/api/ws/global' failed`。
**原因**：Vite 默认只代理 HTTP 请求，不代理 WebSocket 协议。
**解决**：在 `vite.config.ts` 的 `server.proxy` 中，为 `/api` 规则显式添加 `ws: true`。

#### 3、遗漏路由挂载导致 `/api/banks` 报 404
**现象**：前端加载题库分组时提示 404，且 WebSocket 通信时好时坏。
**原因**：在 Day 56 重构 `problem_plugin/__init__.py` 时，遗漏了 `bank_api` 和 `bank_crud_api` 的导入与返回，导致插件启动时直接抛出异常，连累了原本正常的接口。
**解决**：补全 `get_routers()` 返回值中的 `bank_router` 和 `bank_crud_router`。
