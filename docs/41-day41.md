### 二、判题容器化修复（Worker 与跨容器沙箱）

#### 1、新增 Worker 容器
**现象**：打包版提交代码一直显示“排队中”，`docker ps` 只有三个容器，缺少判题消费者。
**解决**：
- 在 `docker-compose.yml` 中新增 `worker` 服务。
- 复用 `backend` 镜像，覆盖 `command: arq app.plugins.judge_plugin.worker.WorkerSettings`。
- 设置 `SKIP_MIGRATIONS: "1"`，避免与 backend 启动时竞争执行数据库迁移。
- 将宿主机的 `/var/run/docker.sock` 挂载到 worker 容器内，允许其调用 Docker。

#### 2、跨容器判题路径映射（DooD）
**现象**：Worker 在容器内运行，生成判题临时文件后，交给宿主机的 Docker 去挂载时，宿主机找不到这个临时目录，导致编译错误或运行错误。
**解决**：
- 创建 Docker 命名卷 `sandbox_data`。
- Worker 和判题容器同时挂载该卷。
- 修改 `sandbox.py` 中的 `sandbox_workspace()`，判断如果在容器内（`IN_DOCKER=1`），则使用 `/sandbox` 作为工作目录。
- 同时补齐了 `SandboxResult` 等类的 `runtime_ms` 字段，使用 `time.perf_counter()` 记录真实运行耗时。

### 三、Docker 环境探测与用户引导

**现象**：朋友电脑未启动 Docker 时，直接抛出底层 `npipe` 错误；国内网络拉取镜像超时抛出满屏红色报错，普通用户无法理解。
**解决**：全面重构 `backend_launcher.rs`。
- 实现 `probe_docker()` 状态机，按顺序检测：未安装、Daemon 未启动、缺少 Compose 插件、版本过旧。
- 多路径查找 docker，兼容系统级路径、用户级路径及 `PATH` 环境变量。
- 捕获 `docker compose up -d` 的 STDERR，识别 `auth.docker.io` 报错，弹窗引导用户配置国内镜像加速器。
- 识别 `failed to connect to the docker api` 报错，弹窗提醒启动 Docker Desktop。

### 四、应用配置与资源更新机制

**现象**：开发过程中频繁修改 `docker-compose.yml` 增加 Worker，但朋友装新版 MSI 后依然跑旧配置（因为 `%APPDATA%` 已经存在，旧代码跳过了覆盖）。
**解决**：修改 `extract_assets_if_needed()`。
- 无论本地是否存在，每次启动时强制用 exe 内置的最新 `docker-compose.yml` 和 `.env.example` 覆盖本地文件。
- 强制覆盖解压 `backend` 源码，确保后端逻辑（如沙箱逻辑）与桌面端版本完全一致，彻底解决版本不匹配问题。

### 五、前端时区显示修复

**现象**：提交记录显示的时间比北京时间慢 8 小时。
**原因**：数据库存的是 UTC 时间（15:51），后端返回的字符串无时区标识，前端 JS 将其当做本地时间直接渲染。
**解决**：修改前端 `SubmissionList.vue` 和 `ProblemDetail.vue` 的 `formatTime` 函数，检测字符串若没有时区后缀，则手动补充 `Z`，让浏览器自动转换为本地时区。

### 七、踩坑记录

#### 1、Docker Desktop 退出导致数据库掉线
**原因**：`docker-compose.yml` 中 `postgres` 缺少 `restart: unless-stopped` 策略。Docker Desktop 重启时不会自动拉起 Postgres，导致 backend 连接失败。
**解决**：为所有核心服务添加 `restart: unless-stopped`。

#### 2、Entrypoint 执行顺序错误
**原因**：Worker 容器如果也执行 `alembic upgrade head`，可能与 backend 并发迁移导致锁死。
**解决**：在 Compose 文件中通过环境变量 `SKIP_MIGRATIONS=1` 控制 worker 的启动脚本跳过迁移。

#### 3、Windows 下的 Docker Socket 挂载
**原因**：在 Docker Compose 中写 `//./pipe/docker_engine` 会导致 WSL2 路径转换异常。
**解决**：直接使用标准 Linux 路径 `/var/run/docker.sock:/var/run/docker.sock`，Docker Desktop 会自动在底层桥接命名管道。
