# 第 55 天：插件安装异步化与进度轮询

### 一、今日目标
- 解决一键安装重型微服务插件时，因 `pip install` 或 `docker compose` 耗时过长导致的前端 Axios 请求超时（15 秒）问题。
- 提升用户体验，将阻塞式的“假死”安装改为异步后台执行，并提供实时的安装进度反馈。

### 二、核心实现

#### 1、后端：异步协程与状态维护
- 将 `market_api.py` 中的 `install_plugin` 接口改为“触发即返回”。
- 使用 `asyncio.create_task(_background_install(...))` 在后台执行完整的下载、解压、`pip install` 和 `on_install` 逻辑，不阻塞 FastAPI 的主事件循环。
- 引入全局字典 `_install_status` 维护每个插件的安装阶段状态（`downloading`、`extracting`、`installing_deps`、`starting_service`、`success`、`error`）。
- 新增 `GET /api/admin/market/install_status/{plugin_name}` 接口，供前端随时轮询查询。

#### 2、前端：轮询机制与动态文案
- `Settings.vue` 的安装逻辑从 `await api.post` 阻塞改为开启 `setInterval` 定时轮询。
- 根据后端返回的 `status` 字段，利用 Vue 的 `computed` 动态更新全屏遮罩上的提示文案（如：“正在下载插件包...”、“正在启动微服务，请稍候...”）。
- 彻底移除了原先依赖 Axios 长连接硬等的方式。

### 三、踩坑记录

#### 后端路由 404
**现象**：前端点击安装后，轮询请求 `GET /api/admin/market/install_status/ocr_plugin` 持续报 404。
**原因**：Day 52 之后，后端代码是通过 `COPY . .` 打进镜像的，修改了 `market_api.py` 后只执行了 `docker restart`，导致容器内跑的还是旧代码。
**解决**：执行 `docker compose build backend && docker compose up -d backend` 重新构建镜像后，路由成功挂载。
