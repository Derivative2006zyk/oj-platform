# 第4天：分类与题目查询 API

### 一、三层结构

```
请求 → 路由层 (api.py) → 服务层 (service.py) → 模型层 (models)
         ↓                    ↓
      参数校验           业务逻辑 + 数据库
         ↓                    ↓
      响应封装           返回 ORM 对象或字典
```

原则：
- 路由层负责：解析 HTTP 请求参数、调用服务层、封装响应、抛出 HTTP 异常
- 服务层负责：构造 SQL 查询、执行数据库操作、返回业务数据
- 模型层负责：定义表结构、字段约束、关联关系

依赖注入：
```python
async def get_db():
    async with async_session() as session:
        yield session
```
`yield` 之前的代码在请求前执行，之后的代码在响应后执行。FastAPI 会在响应完成后自动恢复生成器，执行 finally 块，关闭会话。

### 三、分页与筛选的实现

```python
async def get_problem_list(db, page=1, page_size=10, category_id=None, ...):
    query = select(Problem)
    if category_id:
        query = query.where(Problem.category_id == category_id)
    if difficulty:
        query = query.where(Problem.difficulty == difficulty)
    if type:
        query = query.where(Problem.type == type)
    if tag:
        query = query.where(Problem.tags.contains([tag]))
    if keyword:
        query = query.where(Problem.title.ilike(f"%{keyword}%"))

    count_query = select(func.count()).select_from(query.subquery())
    total = (await db.execute(count_query)).scalar()

    query = query.order_by(Problem.id.desc()).offset((page - 1) * page_size).limit(page_size)
    result = await db.execute(query)
    problems = result.scalars().all()

    return {"total": total, "page": page, "page_size": page_size, "items": problems}
```

#### 关键技术点

| 技术点 | 说明 |
|---|---|
| 动态条件 | 依次判断参数是否非空，逐条 where |
| 总数查询 | `select(func.count()).select_from(query.subquery())` |
| scalar() | 返回单个值，不是对象 |
| contains([tag]) | JSONB 数组包含查询 |
| ilike | 不区分大小写的模糊匹配 |
| offset/limit | 标准分页 |

#### 为什么需要子查询统计总数
直接对 query 执行 count 无法自动去除 order_by 与 limit，可能导致 SQL 语义错误。将 query 变为 subquery 后再 count，等价于 `SELECT COUNT(*) FROM (原查询) AS sub`。

#### scalar() 与 scalar 的差异
- `.scalar` 是方法对象，直接返回不会求值
- `.scalar()` 是方法调用，返回查询结果的第一行第一列

### 四、详情接口的题型差异化

#### 1、设计思路
先查询 problems 主表得到基础字段，再按 type 查询子表。

| 题型 | 附加数据 |
|---|---|
| algorithm | test_cases（is_example=True） |
| choice | options（JSONB 字段，直接读） |
| fill_blank | blanks（JSONB 字段，直接读） |
| proof | 无附加 |
| research | subprojects（按 sort_order 排序） |

#### 2、关键实现
```python
async def get_problem_detail(db, problem_id):
    problem = await db.get(Problem, problem_id)
    if not problem:
        return None
    detail = {
        "id": problem.id, "title": problem.title,
        "description": problem.description, "type": problem.type,
        "difficulty": problem.difficulty, "tags": problem.tags,
        "category_id": problem.category_id, "explanation": problem.explanation,
        "options": problem.options, "blanks": problem.blanks,
        "test_cases": [], "subprojects": []
    }
    if problem.type == "algorithm":
        result = await db.execute(
            select(TestCase).where(
                TestCase.problem_id == problem_id, TestCase.is_example == True
            )
        )
        detail["test_cases"] = [
            {"input_data": tc.input_data, "expected_output": tc.expected_output}
            for tc in result.scalars().all()
        ]
    if problem.type == "research":
        result = await db.execute(
            select(ResearchSubproject)
            .where(ResearchSubproject.problem_id == problem_id)
            .order_by(ResearchSubproject.sort_order)
        )
        detail["subprojects"] = [
            {"id": sp.id, "title": sp.title, "description": sp.description,
             "hint": sp.hint, "reference_links": sp.reference_links,
             "answer_guide": sp.answer_guide, "sort_order": sp.sort_order}
            for sp in result.scalars().all()
        ]
    return detail
```

#### 3、答案隔离的设计
详情接口不返回 answer 字段，需要查看答案时通过单独的 `/problems/{id}/answer` 接口。意义：前端可以控制"查看答案"按钮的触发时机，用户不会在查看详情时意外看到答案。

### 五、标签聚合

```python
async def get_all_tags(db):
    result = await db.execute(select(Problem.tags))
    all_tags = set()
    for row in result.scalars().all():
        if row:
            all_tags.update(row)
    return sorted(list(all_tags))
```

原理：查询所有题目的 tags 列（JSONB 数组），将每行的数组元素合并到 Python set 中，自动去重，最后排序返回。

### 六、API 路由

```python
router = APIRouter(prefix="/api", tags=["problems"])

@router.get("/categories", response_model=list[CategoryResponse])
async def get_categories(db: AsyncSession = Depends(get_db)):
    return await service.get_all_categories(db)

@router.get("/problems")
async def list_problems(
    page: int = Query(1, ge=1),
    page_size: int = Query(10, ge=1, le=50),
    category_id: int = Query(None),
    difficulty: int = Query(None, ge=1, le=5),
    type: str = Query(None),
    tag: str = Query(None),
    keyword: str = Query(None),
    db: AsyncSession = Depends(get_db),
):
    return await service.get_problem_list(db, page, page_size, category_id, difficulty, type, tag, keyword)

@router.get("/problems/{problem_id}")
async def get_problem(problem_id: int, db: AsyncSession = Depends(get_db)):
    detail = await service.get_problem_detail(db, problem_id)
    if not detail:
        raise HTTPException(status_code=404, detail="Problem not found")
    return detail

@router.get("/problems/{problem_id}/answer", response_model=AnswerResponse)
async def get_answer(problem_id: int, db: AsyncSession = Depends(get_db)):
    problem = await db.get(Problem, problem_id)
    if not problem:
        raise HTTPException(status_code=404, detail="Problem not found")
    return {"answer": problem.answer, "explanation": problem.explanation}

@router.get("/tags")
async def get_tags(db: AsyncSession = Depends(get_db)):
    return await service.get_all_tags(db)
```

路由顺序：FastAPI 按定义顺序匹配路由。静态路径应写在动态路径之前。

### 七、RESTful API 设计原则

| 原则 | 实现 |
|---|---|
| 资源命名用复数 | /problems, /categories, /tags |
| 动词隐含在 HTTP 方法中 | GET 查询、POST 创建、PUT 更新、DELETE 删除 |
| 分页用 query 参数 | ?page=1&page_size=10 |
| 筛选用 query 参数 | ?category_id=1&difficulty=2 |
| 404 用于资源不存在 | raise HTTPException(404) |

### 八、注意事项

#### 1、路由单复数一致
- 资源命名统一用复数：`/problems`、`/categories`、`/tags`。
- 若写成 `/problem`、`/category`、`/tag`，前端调用时必须对应，否则 404。
- 本项目统一用复数。

#### 2、详情路由必须存在
- `GET /api/problems/{problem_id}` 是详情接口，必须定义。
- 若遗漏，会返回 FastAPI 默认 404 `{"detail": "Not Found"}`，容易误判为数据不存在。
- 判别方法：默认 404 的 detail 是 `"Not Found"`（英文首字母大写），自定义 404 是中文或自定义消息。

#### 3、scalar 后必须加括号
- `(await db.execute(count_query)).scalar` 少括号时，`total` 返回的是方法对象，JSON 序列化后变成 `{}`。
- 正确写法：`(await db.execute(count_query)).scalar()`。

#### 4、ilike 与 like
- `ilike` 不区分大小写，适合搜索。
- `like` 区分大小写。
- PostgreSQL 特有 `ilike`，其他数据库可能不支持。

#### 5、JSONB 的 contains
- `Problem.tags.contains([tag])` 判断 tags 数组是否包含指定元素。
- 必须传列表，不能传字符串 `Problem.tags.contains(tag)`。

#### 6、字段名不要拼错
- `desc()` 不是 `dese()`。
- 拼写错误会报 `AttributeError`，错误信息里往往有 "Did you mean: 'desc'?" 之类的提示。

#### 7、路由顺序
- 静态路径写在动态路径之前。
- 例如 `@router.get("/problems/featured")` 要写在 `@router.get("/problems/{problem_id}")` 之前。
- 本项目暂无此问题，但后续扩展时需注意。

#### 8、中文乱码
- 中文注释和字符串必须用 UTF-8 保存。
- 若终端显示乱码（如 `棰樼洰涓嶅瓨鍦?`），说明文件是 GBK 编码。
- 建议统一改为英文注释，避免跨平台问题。
