# 第 48 天：插件热重载与 Tauri 自动重启

### 一、今日目标

- 在 Tauri (Rust) 侧新增指令，调用宿主机的 Docker Compose 重启容器。
- 前端实现安装完成后自动调起重启逻辑，并加入全屏倒计时遮罩。
- 解决后端重启期间前端过早请求导致的“无法连接到服务器”问题。
- 解决安装完成后导航栏未能自动更新的响应式问题。

### 二、核心实现

#### 1、Tauri 侧：新增重启指令
- 在 `backend_launcher.rs` 中实现 `restart_backend` 函数。
- 通过 `docker compose restart backend worker` 重启容器，并复用 `wait_for_backend` 进行 TCP 端口探测。
- 在 `main.rs` 中注册 `restart_backend_cmd`，供前端通过 `invoke` 调用。

#### 2、前端侧：全屏遮罩与降级处理
- 在 `Settings.vue` 的插件安装逻辑中判断环境：如果是 Tauri，则显示全屏 Loading 遮罩（带有秒数倒计时动画）；如果是浏览器/移动端，则提示“安装成功，请手动重启”。
- 重启完成后的跳转逻辑，从 `window.location.href = '/'`（整体刷新）改为了**不跳转**，仅通过更新 Pinia 状态来触发导航栏渲染。

#### 3、解决“重启后立刻请求失败”的竞态问题
- **现象**：Tauri 重启完成后，前端立刻调用 API 或跳转路由，概率性报“无法连接到服务器”和空题库。
- **原因**：Docker 端口通了，但 FastAPI 内部还在执行 `alembic` 迁移，API 路由尚未挂载完毕。
- **解决**：在前端加入**主动轮询机制**。调用 `invoke` 等待端口就绪后，前端再循环请求 `GET /api/plugins/ui`，直到请求成功返回，才移除遮罩层并提示成功。

### 三、踩坑记录

#### 1、导航栏不自动刷新
**现象**：安装并重启完毕后，左侧/顶部导航栏没有出现新插件的菜单，必须手动点一下“设置”再点回来才会出现。
**原因**：前端使用了 `window.location.href = '/'` 强制刷新整个页面，但在 Tauri 的 WebView 中，有时会命中浏览器的强缓存，或者是路由跳转的瞬间导致 Vue 组件生命周期错乱。
**解决**：放弃了强制跳转页面，改为在轮询确认 API 就绪后，直接更新 Pinia 的 `pluginStore.plugins`。Vue 的响应式系统会自动让导航栏渲染出新菜单，实现了无感热重载。
