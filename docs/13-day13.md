#### 3、关键坑：preview 模式没有代理

Vite 的 `server.proxy` 只作用于 dev（5173），preview（4173）需要单独配置 `preview.proxy`。

**必须同时配置两项**：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true
      }
    }
  },
  preview: {
    port: 4173,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true
      }
    }
  }
})
```

配置后 **必须重启 preview**（`Ctrl + C` 后重新 `npm run preview`），热更新不会应用新代理。

#### 4、关键坑：preview 用的是 dist 打包产物

改了源码（如 `api.ts`、`MarkdownRenderer.vue`）后：

- **dev（5173）**：热更新自动生效
- **preview（4173）**：必须重新 `npm run build` 才生效

两者区别：

| 模式 | 端口 | 用的代码 | 生效方式 |
|---|---|---|---|
| dev | 5173 | 实时源码 | 热更新 |
| preview | 4173 | dist 打包产物 | 需重新 build |

#### 5、关键坑：Markdown 图片 URL 兼容

数据库中的图片 Markdown 可能存的是相对路径 `/api/images/3`。前端渲染时浏览器会基于当前页面 URL 补全，在 preview 模式下会变成 `http://localhost:4173/api/images/3`，若代理未生效就 404。

**解决方案**：在 `MarkdownRenderer.vue` 中把相对路径替换为后端绝对路径：

```typescript
const BACKEND_URL = 'http://localhost:8000'

const rendered = computed(() => {
  if (!props.content) return ''
  let content = String(props.content)

  // 兼容旧格式单数 URL
  content = content.replace(/\/api\/image\//g, '/api/images/')

  // 把 Markdown 图片中的相对路径改为后端绝对地址
  content = content.replace(
    /!\[([^\]]*)\]\(\/api\//g,
    `![$1](${BACKEND_URL}/api/`
  )

  return marked(content)
})
```

这样图片请求直接打到 8000，绕过 Vite 代理。

**生产环境需替换**：用环境变量 `import.meta.env.VITE_BACKEND_URL`，开发环境填 `http://localhost:8000`，生产环境填空字符串。

### 四、Nginx 部署配置

#### 1、创建 deploy/nginx.conf

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/oj-platform;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 10M;
    }

    location ~* \.(jpg|jpeg|png|webp|gif|ico|css|js|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml;
    gzip_min_length 1000;
}
```

#### 2、关键配置

| 配置 | 作用 |
|---|---|
| `try_files $uri $uri/ /index.html` | history 模式回退，避免刷新 404 |
| `location /api/` | 转发 API 到后端 8000 |
| `proxy_set_header` | 保留客户端 Host、IP |
| `client_max_body_size 10M` | 允许上传大文件 |
| `expires 7d` | 静态资源缓存 |
| `gzip on` | 压缩传输 |

#### 3、语法验证

用 nginx 镜像验证配置：

```
docker run --rm -v E:\github_project\oj-platform\deploy\nginx.conf:/etc/nginx/conf.d/default.conf nginx:alpine nginx -t
```

预期：

```
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

#### 4、部署流程

在 Linux 服务器上：

```bash
# 1. 上传前端打包产物
scp -r frontend/dist/* user@server:/var/www/oj-platform/

# 2. 启动后端
cd /path/to/oj-platform
docker compose up -d

# 3. 配置 Nginx
sudo cp deploy/nginx.conf /etc/nginx/conf.d/oj-platform.conf
sudo nginx -t
sudo systemctl reload nginx
```
