### 二、列表页增强1：URL 同步筛选条件

#### 1、目标

筛选条件同步到 URL query，刷新后保留，可分享链接。

#### 2、原理

- 使用 `useRoute()` 读取 URL query 初始化筛选条件
- 使用 `router.replace()` 在筛选条件变化时更新 URL
- 用 `replace` 而不是 `push`，避免污染浏览器历史记录

#### 3、关键代码

```typescript
import { useRouter, useRoute } from 'vue-router'

const router = useRouter()
const route = useRoute()

// 从 URL 初始化
const page = ref(Number(route.query.page) || 1)
const keyword = ref((route.query.keyword as string) || '')
const difficulty = ref<number | null>(
  route.query.difficulty ? Number(route.query.difficulty) : null
)
const selectedTag = ref((route.query.tag as string) || '')
const selectedType = ref((route.query.type as string) || '')
const selectedCategory = ref<number | null>(
  route.query.category_id ? Number(route.query.category_id) : null
)

// 同步到 URL
function syncUrl() {
  const query: Record<string, string> = {}
  if (page.value > 1) query.page = String(page.value)
  if (keyword.value) query.keyword = keyword.value
  if (difficulty.value) query.difficulty = String(difficulty.value)
  if (selectedTag.value) query.tag = selectedTag.value
  if (selectedType.value) query.type = selectedType.value
  if (selectedCategory.value) query.category_id = String(selectedCategory.value)

  router.replace({ query })
}

// loadProblems 末尾调用 syncUrl()
```

#### 4、关键点

| 变化点 | 说明 |
|---|---|
| 引入 `useRoute` | 读取当前 URL 的 query |
| 初始值从 route.query 读取 | 数字需 `Number()` 转换 |
| 新增 `syncUrl` 函数 | 将筛选条件同步到 URL |
| 使用 `router.replace` | 不产生新历史记录 |

#### 5、URL 变化示例

筛选后 URL 类似：

```
http://localhost:5173/?category_id=1&difficulty=2&keyword=两数
```

刷新后筛选条件保留，分享 URL 后打开效果一致。

### 三、列表页增强2：防抖搜索

#### 1、目标

用户输入停止 500ms 后自动搜索，避免每输入一个字就发请求。

#### 2、原理

使用 `watch` 监听 `keyword` 变化，每次变化时清除上一个定时器，重新设置一个新定时器。当用户停止输入 500ms 后，定时器触发 `search()`。

#### 3、代码

```typescript
import { watch, onUnmounted } from 'vue'

let searchTimer: number | null = null

watch(keyword, () => {
  if (searchTimer) clearTimeout(searchTimer)
  searchTimer = window.setTimeout(() => {
    search()
  }, 500)
})

onUnmounted(() => {
  if (searchTimer) clearTimeout(searchTimer)
})
```

#### 4、防抖与节流的区别

| 概念 | 行为 | 适用场景 |
|---|---|---|
| 防抖 (debounce) | 停止输入 N 毫秒后触发一次 | 搜索框 |
| 节流 (throttle) | 每隔 N 毫秒触发一次 | 滚动、拖拽 |

#### 2、创建 utils/marked.ts

在 `frontend/src/utils/` 下新建 `marked.ts`：

```typescript
import { marked } from 'marked'
import { markedHighlight } from 'marked-highlight'
import hljs from 'highlight.js'
import 'highlight.js/styles/github.css'

marked.use(
  markedHighlight({
    langPrefix: 'hljs language-',
    highlight(code, lang) {
      if (lang && hljs.getLanguage(lang)) {
        try {
          return hljs.highlight(code, { language: lang }).value
        } catch (e) {
          console.error('高亮失败：', e)
        }
      }
      return hljs.highlightAuto(code).value
    }
  })
)

export { marked }
```

#### 3、修改 MarkdownRenderer.vue 的导入

```typescript
// 从 utils 导入，而不是从 marked 包
```

#### 4、关键点

- `marked.use` 必须放在模块顶层，不能写在组件的 `<script setup>` 内部
- 写在组件内部会导致每次实例化都重复注册扩展，输出被指数级叠加 HTML 转义，最终浏览器卡死

### 十、注意事项

#### 1、URL 同步的类型转换

从 `route.query` 读取的值都是字符串，需要转换：

| 类型 | 转换 |
|---|---|
| 数字 | `Number(route.query.xxx)` |
| 数字或 null | `route.query.xxx ? Number(route.query.xxx) : null` |
| 字符串 | 直接使用 |

#### 2、router.replace 与 router.push

- `router.push`：新增历史记录
- `router.replace`：替换当前历史记录

筛选条件变化频繁，应用 `replace`，避免用户点击"后退"时回退到每一次筛选状态。

#### 3、防抖定时器的类型

浏览器环境中 `setTimeout` 返回 `number`。TypeScript 中应写：

```typescript
let timer: number | null = null
timer = window.setTimeout(...)
```

#### 4、onUnmounted 清理定时器

组件卸载时清除定时器，避免内存泄漏。

#### 5、marked.use 必须放模块顶层

**这是本项目踩过最大的坑。** 写在 `<script setup>` 内部会导致每次组件实例化都重复注册 highlight 扩展，输出被指数级叠加 HTML 转义：

- 第一次渲染：原始 Markdown → HTML
- 第二次渲染：上一次的输出被当作 Markdown 又渲染，`<span>` 转义为 `&lt;span`
- 第三次渲染：又一层 `&amp;lt;span`
- 最终变成 `&amp;amp;amp;lt;span...`，浏览器卡死

正确做法是放到独立的 `utils/marked.ts` 模块中，模块只在首次导入时执行一次。

#### 6、v-html 的安全风险

Markdown 渲染使用 `v-html`，若内容含 `<script>` 会被执行。当前内容由管理员录入，可接受。若对外开放：

```
npm install dompurify
```

```typescript
import DOMPurify from 'dompurify'
const rendered = computed(() => DOMPurify.sanitize(marked(props.content)))
```

#### 7、test_cases 数组可能为空

算法题若没配示例用例，`test_cases` 为空数组。模板用 `v-if="problem.test_cases.length > 0"` 避免渲染空区域。

#### 8、子项目排序

后端已按 `sort_order` 排序返回，前端无需再排序。

#### 9、删除操作的二次确认

`confirm()` 是浏览器原生弹窗，样式不可自定义。可替换为自定义 Modal，本项目暂用原生。

#### 10、图片 CORS

Markdown 中的图片指向 `http://localhost:8000/api/images/1`。若浏览器报 CORS 错误，检查后端 CORS 中间件。

#### 11、中文字符的 URL 编码

`router.replace({ query: { keyword: '两数' } })` 会自动编码为 `%E4%B8%A4%E6%95%B0`。

#### 12、调试技巧

| 工具 | 用途 |
|---|---|
| F12 Network | 查看请求 URL、状态码、响应 |
| F12 Console | 查看 JS 错误和 console.log |
| Vue DevTools | 查看组件树、props、data |

#### 13、常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `Cannot read property 'xxx' of null` | `problem.value` 为 null 时访问属性 | 模板中加 `v-if="problem"` |
| `Failed to resolve component` | 组件未导入 | 检查 import 路径 |
| `[Vue warn]: Invalid prop` | props 类型不匹配 | 检查 props 定义 |
| `Network Error` | 后端未启动 | 启动 uvicorn |
| 页面卡死 | marked.use 被反复调用 | 移到模块顶层 |
