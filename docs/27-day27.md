### 二、JVM 参数

```
-Xmx200m
-Xms200m
-Xss8m
-XX:+UseSerialGC
-XX:MaxMetaspaceSize=64m
```

容器限制 256 MB，堆 200 MB，预留 56 MB 给 JVM 自身。

**理由**：

- `-Xmx` < 容器内存 × 80%，避免 OOM Kill
- `-Xms` = `-Xmx`，无动态扩展
- `-Xss8m`，线程栈受限，防爆栈
- `UseSerialGC`，单核容器启动快

### 三、编译缓存

原来：每个测试点重新 `javac`

现在：

```
1. compile_java(tmpdir) → 一次
2. 逐个测试点：run_java_compiled(tmpdir) → 只运行
```

**性能对比**：

| 场景 | 之前 | 现在 |
|---|---|---|
| 1 个测试点 | ~3s | ~2s |
| 5 个测试点 | ~15s | ~7s |

`tmpdir` 复用，`.class` 文件持久。

### 四、worker 并发

```python
class WorkerSettings:
    max_jobs = 2
    job_timeout = 60
    keep_result = 3600
```

**为什么 2**：

- 每任务最多 1 个容器
- 2 并发 → 总内存 ~512 MB
- 桌面端可接受

### 六、踩坑记录

#### 1、JVM OOM 误判

`-Xmx` 未限制时，JVM 申请超容器内存 → Docker 杀 → 误判 MLE。

**解决**：显式 `-Xmx200m`。

#### 2、编译重复

初版每个测试点都编译，5 个测试点 5 次 javac。

**解决**：编译移出循环，`tmpdir` 复用。

#### 3、worker 并发爆炸

未限制 `max_jobs` 时，10 个任务同时启动 10 个 Docker 容器。

**解决**：`max_jobs = 2`。

#### 4、`-encoding UTF-8` 防中文乱码

`javac` 默认用系统编码，用户代码含中文可能编译失败。显式指定 UTF-8 解决。
