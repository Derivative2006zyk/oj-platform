# 第 59 天：离线优先体验与本地数据缓存

### 一、今日目标
- 解决弱网或后端宕机时，前端页面白屏报错、无法查看历史题库的痛点。
- 实现离线优先（Offline-First）架构：应用启动时优先渲染本地缓存，随后在后台静默同步网络数据。
- 提升网络异常时的容错率，避免局部接口超时导致整个页面崩溃。

### 二、核心实现

#### 1、极简本地缓存工具
- 放弃引入体积较大且存在兼容性问题的异步第三方库（localforage），改用浏览器原生同步 API `localStorage`。
- 封装 `utils/cache.ts`，提供 `setCache` 与 `getCache`，保证在各类 WebView 中绝对稳定。

#### 2、列表页离线改造（ProblemList.vue）
- **先缓存后请求**：在 `onMounted` 生命周期中，立即读取 `localStorage` 中的题库列表缓存并渲染。
- **后台静默刷新**：渲染缓存的同时发起网络请求，成功后无感替换数据并更新缓存，同时关闭离线提示。
- **容错处理**：拆分原先的 `Promise.all`，将分类、标签、题库、题目列表的请求分别独立包裹在 `try-catch` 中，确保非核心接口超时不会阻断主列表的展示。

#### 3、详情页离线改造（ProblemDetail.vue）
- 使用带 `problem_id` 的独立 Key 缓存详情数据和答案数据。
- 同样采用“先读缓存极速渲染，后发请求静默更新”的策略。
- 将原本耦合在 `loadProblem` 里的草稿恢复逻辑抽离为 `restoreDraft()`，保证无论数据来源于网络还是缓存，表单草稿（代码、输入内容）都能正确回显。
- 增加了顶部的「当前离线模式」提示横幅。

#### 4、修复控制台报错
- 修改 `stores/plugin.ts` 的异常捕获逻辑，当获取插件列表超时时，改用 `console.warn` 静默处理，避免断网时控制台满屏红字。

### 三、踩坑记录

#### 1、Vite 代理超时假死
**现象**：使用 `localforage` 方案时，关掉后端，页面依然要白等 15 秒才出缓存。
**原因**：Axios 默认超时时间过长，且 Vite 代理在失去后端时会保持挂起（hang up），导致前端无法立刻触发 catch 块。
**解决**：缩短 Axios 的超时时间（由 15s 改为 3s），并放弃在请求失败后才读缓存的逻辑，改为首屏直接同步读取缓存，彻底抹平等待感。

#### 2、Promise.all 的连锁崩溃
**现象**：只是断网，但连原本已经缓存的列表都没了，直接触发全局报错。
**原因**：初始化时使用了 `Promise.all([getCategories(), getAllTags(), listBanks()])`，只要其中一个请求（例如获取分类）超时，整个 `Promise.all` 就会 reject，导致后续的 `loadProblems()` 根本没被执行。
**解决**：将并发请求拆分为独立的 `try-catch` 块，让接口互不干扰，核心任务优先执行。
