### 二、插件协议

#### 1、Plugin 抽象基类

```python
class Plugin(ABC):
    name: str
    version: str
    dependencies: list[str]

    @abstractmethod
    async def on_load(self) -> None: ...

    async def on_enable(self) -> None: ...
    async def on_disable(self) -> None: ...
    async def on_unload(self) -> None: ...

    def get_routers(self) -> list[APIRouter]:
        return []
```

#### 2、生命周期

- `on_load`：注册路由、订阅事件
- `on_enable`：激活业务
- `on_disable`：停用业务
- `on_unload`：释放资源

### 三、PluginRegistry

#### 1、核心方法

- `register(cls)`：注册
- `discover(package)`：扫描
- `load_all()`：拓扑排序 + 加载
- `unload_all()`：逆序卸载
- `enable(name)` / `disable(name)`：单个启停
- `collect_routers()`：收集路由

#### 2、依赖拓扑排序

用 DFS 检测循环依赖，按依赖顺序加载。

### 四、@register_plugin 装饰器

```python
def register_plugin(cls):
    get_plugin_registry().register(cls)
    return cls
```

### 五、problem_plugin 适配

### 八、注意事项

#### 1、装饰器在 import 时执行

模块顶层必须定义插件类。

#### 2、测试用独立实例

避免污染全局单例。

#### 3、订阅在 on_load，启动监听在 start_listening

插件订阅只写入本地 `_handlers`，Redis 真正订阅在 `start_listening()`。

#### 4、路由挂载时机

必须在应用创建时完成，不能放到 lifespan 里。

#### 5、循环依赖检测

`_topological_order` 抛 `ValueError`。

### 十一、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动日志无 `[PluginRegistry]` | 未调用 discover | 检查 main.py 顶层 |
| 插件未注册 | 缺少 @register_plugin | 检查类装饰器 |
| 重名报错 | 两个插件同名 | 改 name |
| 循环依赖报错 | dependencies 成环 | 拆依赖 |
| 事件订阅无效 | start_listening 未调用 | 检查 lifespan |
| 路由 404 | 路由未挂载 | 检查 collect_routers 与 include_router |
