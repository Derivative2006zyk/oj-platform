<script setup lang="ts">
import { ref, reactive, computed, onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import {
  getCategories,
  getProblemDetail,
  getProblemAnswer,
  createProblem,
  updateProblem,
  type Category
} from '../api/problem'

const route = useRoute()
const router = useRouter()

const isEdit = computed(() => route.params.id !== undefined)

// 管理员密钥
const adminKey = ref(localStorage.getItem('admin_key') || 'admin-key-change-me')

// 分类列表
const categories = ref<Category[]>([])

// 标签输入（逗号分隔的字符串）
const tagsInput = ref('')

// 提交状态
const submitting = ref(false)

// 表单数据
const form = reactive({
  title: '',
  category_id: 1,
  type: 'algorithm',
  difficulty: 1,
  description: '',
  answer: '',
  explanation: '',
  // 以下字段在第11天使用
  test_cases: [] as any[],
  options: [] as any[],
  blanks: [] as any[],
  subprojects: [] as any[]
})

// 保存表单
async function submit() {
  // 基础校验
  if (!form.title.trim()) {
    alert('请填写标题')
    return
  }
  if (!form.description.trim()) {
    alert('请填写题目描述')
    return
  }
  if (!adminKey.value.trim()) {
    alert('请填写管理员密钥')
    return
  }

  // 保存密钥到本地
  localStorage.setItem('admin_key', adminKey.value)

  // 组装请求数据
  const data: any = {
    title: form.title.trim(),
    category_id: form.category_id,
    type: form.type,
    difficulty: form.difficulty,
    description: form.description,
    answer: form.answer || null,
    explanation: form.explanation || null,
    tags: tagsInput.value
      .split(',')
      .map(t => t.trim())
      .filter(t => t),
    // 以下字段在第11天完善
    test_cases: [],
    options: null,
    blanks: null,
    subprojects: []
  }

  submitting.value = true
  try {
    if (isEdit.value) {
      const id = Number(route.params.id)
      await updateProblem(id, data)
      alert('更新成功')
    } else {
      await createProblem(data)
      alert('创建成功')
    }
    router.push('/')
  } catch (e: any) {
    const msg = e.response?.data?.detail || e.message || '保存失败'
    alert('保存失败：' + msg)
  } finally {
    submitting.value = false
  }
}

// 取消
function cancel() {
  router.push('/')
}

// 初始化
onMounted(async () => {
  // 加载分类
  categories.value = await getCategories()

  // 编辑模式：回填数据
  if (isEdit.value) {
    const id = Number(route.params.id)
    try {
      const detail = await getProblemDetail(id)
      form.title = detail.title
      form.category_id = detail.category_id
      form.type = detail.type
      form.difficulty = detail.difficulty
      form.description = detail.description
      form.explanation = detail.explanation || ''
      tagsInput.value = detail.tags.join(',')

      // 答案通过单独接口获取
      try {
        const answerData = await getProblemAnswer(id)
        form.answer = answerData.answer || ''
        if (answerData.explanation) {
          form.explanation = answerData.explanation
        }
      } catch (e) {
        console.warn('获取答案失败', e)
      }

      // 以下字段在第11天回填
      // form.test_cases = detail.test_cases
      // form.options = detail.options || []
      // form.blanks = detail.blanks || []
      // form.subprojects = detail.subprojects
    } catch (e) {
      alert('题目不存在')
      router.push('/')
    }
  }
})
</script>

### 五、代码逻辑详解

#### 1、isEdit 判断

```typescript
const isEdit = computed(() => route.params.id !== undefined)
```

- `/admin/problem/new` 无 `id` 参数，`isEdit = false`
- `/admin/problem/5/edit` 有 `id` 参数，`isEdit = true`

用 `computed` 而不是 `ref`，因为路由参数可能在组件生命周期中变化。

#### 2、题型切换的禁用

```vue
<select v-model="form.type" :disabled="isEdit">
```

编辑时禁止修改题型，原因是：
- 不同题型的子表结构不同
- 算法题的 test_cases 与科研项目的 subprojects 无法兼容
- 修改题型需要删除旧数据、创建新数据，复杂度较高

#### 3、标签的处理

- 输入是字符串，如 `"数组,哈希表"`
- 提交时用 `split(',')` 拆分为数组，再 `trim` 去除空格，`filter` 过滤空串
- 编辑时用 `join(',')` 反向拼接

#### 4、答案的初始化

创建时 `form.answer` 初始为空字符串。

编辑时通过 `getProblemAnswer(id)` 单独获取。原因是详情接口不返回 answer 字段（答案隔离设计）。

#### 5、管理员密钥的保存时机

只有在用户点击"保存"时，才把 `adminKey` 写入 `localStorage`。避免输入过程中写入半成品的密钥。

#### 6、提交状态与按钮禁用

```typescript
const submitting = ref(false)
```

提交时置为 true，按钮文本变为"保存中..."，并禁用，防止重复点击。

### 七、注意事项

#### 1、textarea 的字体

`textarea` 默认字体是衬线体，写 Markdown 时不好看。样式里设置了：

```css
font-family: 'Consolas', 'Monaco', monospace;
```

#### 2、v-model 与 number 类型

```vue
<select v-model="form.difficulty">
  <option v-for="d in 5" :key="d" :value="d">{{ d }}星</option>
</select>
```

`:value="d"` 冒号前缀，明确绑定数字 `d`。若写成 `value="d"`（无冒号），会绑定字符串 `"d"`，后端校验会失败。

#### 3、category_id 的初始值

创建模式默认 `category_id = 1`。前提是数据库中有 ID 为 1 的分类。更健壮的写法：

```typescript
onMounted(async () => {
  categories.value = await getCategories()
  if (!isEdit.value && categories.value.length > 0) {
    form.category_id = categories.value[0].id
  }
})
```

#### 4、route.params.id 的类型

`route.params.id` 是字符串，需 `Number()` 转换。若 id 非法（如 `/admin/problem/abc/edit`），`Number('abc')` 返回 `NaN`，请求会 404。健壮写法：

```typescript
if (isNaN(id)) {
  alert('无效的题目 ID')
  router.push('/')
  return
}
```

#### 5、异步请求的错误处理

`getCategories()` 若失败（后端未启动），onMounted 会抛出未捕获异常。生产环境应加 try/catch。

#### 6、子字段的占位

`form.test_cases`、`form.options`、`form.blanks`、`form.subprojects` 在第10天未使用，但已定义在 `form` 中，第11天直接用。

提交时暂时传空值：

- `test_cases: []`
- `options: null`
- `blanks: null`
- `subprojects: []`

#### 7、管理员密钥的默认值

`ref(localStorage.getItem('admin_key') || 'admin-key-change-me')` 使用 `||` 而非 `??`，因为空字符串也应回退到默认值。

#### 8、提交时 trim

用户输入可能有前后空格，提交前 `trim()`。例如标题 `"  测试题  "` 应存为 `"测试题"`。

#### 9、confirm 与 alert 的使用

本项目暂用浏览器原生弹窗。优点是简单，缺点是样式不能自定义。后续可替换为自定义 Toast 组件。

#### 10、题型专属表单的区域

第10天用 `.dynamic-area` 占位，第11天会在其中放入：

- 算法题：测试用例列表编辑
- 选择题：选项列表编辑
- 填空题：空位列表编辑
- 科研项目：子项目列表编辑
- 图片上传（非选择题、非填空题）

目前任何人都能访问 `/admin/problem/new`。后续可在路由守卫中检查 `localStorage.admin_key` 是否存在，不存在则跳转登录页或提示。

### 十、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 分类下拉框为空 | 后端未启动或分类表为空 | 启动后端，检查 `SELECT * FROM categories` |
| 保存后 403 | 密钥错误 | 检查输入，默认 `admin-key-change-me` |
| 保存后 422 | 字段类型不对 | F12 看请求体，检查 difficulty 是否为数字 |
| 编辑页空白 | 题目不存在 | 换用列表页点击进入 |
| 编辑页回填失败 | `getProblemAnswer` 报错 | 查看后端日志；答案字段可能为空 |
| 题型禁用后仍是灰色可选 | 只是视觉禁用 | `disabled` 属性本身会阻止提交 |
| 标签多出空标签 | 输入 `a,,b` | 提交前 filter 已处理 |
| 保存后跳转但不显示新题 | 列表缓存 | 列表页 onMounted 会重新加载 |
