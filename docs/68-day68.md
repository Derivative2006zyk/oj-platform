### 二、核心实现

#### 1、返回键与键盘补偿

移动端返回键默认直接退出应用，软键盘弹出会遮住底部操作区。在 `App.vue` 统一处理：

```ts
function bindBackButton() {
  CapacitorApp.addListener('backButton', ({ canGoBack }) => {
    const closable = document.querySelector('.drawer-mask:not([hidden]), .modal-mask')
    if (closable) return

    if (canGoBack) window.history.back()
    else CapacitorApp.exitApp()
  })
}

function bindKeyboardInset() {
  const vv = window.visualViewport
  if (!vv) return
  const apply = () => {
    const inset = Math.max(0, window.innerHeight - vv.height - vv.offsetTop)
    document.documentElement.style.setProperty('--keyboard-inset', inset + 'px')
  }
  vv.addEventListener('resize', apply)
  vv.addEventListener('scroll', apply)
  apply()
}
```

插件页与主界面统一用 `calc(... + var(--keyboard-inset, 0px))` 作为底部留白。

#### 2、主界面空态与数据防御

截图暴露的真实问题：分类与分组返回空或含无效项时，页面仍渲染了「空胶囊」骨架。

重构后的做法是**原始状态只存不展示**，全部经 `computed` 过滤后暴露：

```ts
const bankItems = computed(() =>
  (Array.isArray(rawBanks.value) ? rawBanks.value : []).filter(
    (b): b is Bank =>
      !!b && typeof b.id === 'number' && Number.isFinite(b.id) &&
      typeof b.name === 'string' && b.name.trim().length > 0
  )
)
```

所有接口返回值统一走 `asArray()` 兜底，非数组一律视为空。三种状态分别处理：

| 状态 | 判定 | 呈现 |
|---|---|---|
| 连不上且无缓存 | `isOffline && !hasCache && 列表为空` | 整页 `EmptyState` |
| 连不上但有缓存 | `isOffline && 列表非空` | 顶部细条 + 缓存时间 |
| 在线但无数据 | 请求成功且列表为空 | 内容区空态，区分「无匹配」与「题库为空」 |

新增 `utils/connectivity.ts` 统一探测 `/health`，`utils/cache.ts` 增加 `oj_cache_` 前缀与 `savedAt` 时间戳，新增 `components/EmptyState.vue` 统一空态外观。

#### 3、桌面端 compose 隔离

问题根源：仓库目录与 `%APPDATA%\oj-platform` 两套 compose 同名 `oj-platform`，后启动的那套会接管容器，把 `postgres` 挂载点从仓库数据目录切到桌面端空目录。

隔离方案：桌面端使用独立文件与独立项目名。

```yaml
# docker-compose.desktop.yml
name: oj-platform-desktop
```

```rust
const DESKTOP_COMPOSE_FILE: &str = "docker-compose.desktop.yml";
const DESKTOP_PROJECT_NAME: &str = "oj-platform-desktop";

c.args(["compose", "-p", DESKTOP_PROJECT_NAME, "-f", DESKTOP_COMPOSE_FILE, "up", "-d"])
```

启动前增加防呆检查，检测到开发环境容器在跑时直接给出引导：

```rust
fn detect_foreign_compose(cmd: &DockerCmd) -> Option<String> {
    let out = run_cmd(cmd, &["ps", "--format", "{{.Names}}"]).ok()?;
    let names = String::from_utf8_lossy(&out.stdout);
    if names.lines().any(|n| {
        let n = n.trim();
        n.starts_with("oj-platform-") && !n.starts_with("oj-platform-desktop-")
    }) {
        return Some("检测到开发环境（oj-platform）的容器仍在运行……".to_string());
    }
    None
}
```

#### 4、插件页离线草稿

识别结果写入 `llm_ocr_draft_v1`，进入插件页自动恢复并展示横幅；断网时禁用导入、保留草稿；网络恢复后自动继续识别。

```js
function saveDraft() {
  if (!state.items.length) { store.remove(DRAFT_KEY); return }
  localStorage.setItem(DRAFT_KEY, JSON.stringify({
    version: 1,
    savedAt: Date.now(),
    type: state.type,
    items: state.items.map(i => ({ title: i.title, desc: i.desc, selected: i.selected }))
  }))
}
```

### 三、踩坑记录

#### 1、桌面端与开发环境共用项目名导致数据「消失」

**现象**：安装新 MSI 后题库变空，`%APPDATA%` 与 `E:\` 各有一套数据，用户误判为数据丢失。
**原因**：两套 compose 项目名均为 `oj-platform`，桌面端启动时复用并重建同名容器，`postgres` 挂载点被切到桌面端目录。
**解决**：核对 `docker inspect` 挂载来源确认数据未丢；改为独立 compose 文件与 `oj-platform-desktop` 项目名；迁移时先备份，再把仓库数据复制到桌面端目录。

#### 2、空数据仍渲染骨架

**现象**：截图满屏空胶囊，显示「共 0 道题目」。
**原因**：分类与分组返回空或含无效项时，模板无条件渲染 `v-for`，`name` 为空就出现无字按钮。
**解决**：原始状态与展示状态分离，用 `computed` 过滤无效项；数据为空时整块不渲染；内容区改为统一空态组件。

#### 3、`ProblemSummary` 缺少 `paper_name`

**现象**：TypeScript 报「类型上不存在属性 paper_name」。
**原因**：后端 `ProblemSummary` 未返回该字段，前端却直接访问。
**解决**：改用 `paper_id` 显示，类型定义补充可选字段，避免依赖未返回的字段。

#### 4、`timeout` 在 conda 环境被遮蔽

**现象**：`timeout /t 20 >nul` 报 `invalid number '/t'`。
**原因**：conda 的 PATH 中存在同名可执行文件，遮蔽系统 `timeout.exe`。
**解决**：改用 `ping -n 21 127.0.0.1 >nul` 等待；被 `^C` 中断也不影响后续判断。

#### 5、`connectivity.ts` 未使用变量导致构建失败

**现象**：`TS6133: 'timer' is declared but its value is never read`。
**解决**：改为 `void setTimeout(...)`，明确忽略返回值。
