# 第 66 天：插件前端独立化与多端适配收尾

### 一、今日目标

在完成试卷三级层级与 AI 清洗链路（Day 65）后，我们发现“录题”体验仍存在三个断点：

1. **插件前端形同虚设**：`llm_ocr_plugin` 的 `frontend/index.html` 是从 AI 聊天页复制的 Vue SFC，但插件页由后端 `StaticFiles` 直接托管，iframe 内既无 Vue 运行时也无构建器，打开即是空白。
2. **iframe 拿不到登录态**：Tauri / Capacitor 下 iframe 指向后端域名，与主应用不同源，读不到 `oj_token` 与 `admin_key`，识别与导入必然 401 / 403。
3. **移动端交互仍在将就**：安全区、输入框缩放、底部工具栏遮挡等问题在真机上集中暴露。

今日的核心任务是：**把插件前端重写为零构建独立 HTML，通过 `postMessage` 打通主应用与插件的上下文，同时完成移动端适配收尾。**

### 二、核心实现

#### 1、插件前端独立化：零构建原生 HTML

放弃 Vue SFC，改为单文件原生 HTML/CSS/JS，可被 `StaticFiles` 直接托管，无需任何打包步骤。

```html
<input id="cameraInput" type="file" accept="image/*" capture="environment" />
<input id="galleryInput" type="file" accept="image/*" />

<script>
  fetch(apiUrl('/plugins/llm_ocr/parse?type=' + state.type), {
    method: 'POST',
    headers: authHeaders(),
    body: form,
    signal: state.abort.signal
  })
</script>
```

页面结构按「选择图片 → 识别设置 → 识别结果」三步推进，移动端采用吸底导入栏与分段式控件。

#### 2、上下文桥接：postMessage 注入登录态

`PluginView.vue` 在 iframe 加载完成或收到 `oj:plugin-ready` 时，把上下文推给子页面。

```ts
function postContext() {
  const win = iframeRef.value?.contentWindow
  if (!win) return

  win.postMessage({
    type: 'oj:context',
    apiBase: getBackendUrl(),
    token: localStorage.getItem('oj_token') || '',
    adminKey: localStorage.getItem('admin_key') || '',
    theme: document.documentElement.getAttribute('data-theme') || 'light'
  }, '*')
}
```

子页面反向支持 `oj:navigate`（跳转登录/设置）与 `oj:set-admin-key`（回写密钥）。同时监听 `data-theme` 变化推送 `oj:theme`，实现明暗模式联动。

#### 3、图片压缩与移动端适配

上传前用 Canvas 将长边压到 1800px、JPEG 质量 0.86，显著降低弱网等待。

```js
function compressImage(file) {
  if (file.size <= 500 * 1024) return Promise.resolve(file)
  // 绘制到 canvas 后 toBlob('image/jpeg', 0.86)
}
```

配套适配：
- `viewport-fit=cover` + `env(safe-area-inset-bottom)` 规避手势条遮挡
- 输入控件字号统一 16px，防止 iOS 聚焦自动缩放
- `NavBar` 隐藏用户名、允许横向滚动，`clamp()` 控制间距
- 设计令牌补充极暗终端风配色，`data-theme` 统一驱动

### 三、踩坑记录

#### 1、iframe 命中磁盘缓存导致插件页始终是旧内容

**现象**：插件包已更新为重写后的 HTML，后端 `curl` 拿到 62,540 字节的新文件，但插件路由里仍显示“这个插件没有UI界面”。
**原因**：网络面板显示 `index.html → 200 / 0 B (disk cache)`。iframe 的缓存语义比主文档顽固，`Ctrl + F5` 只刷新主文档，不会清掉 iframe 的 disk cache。
**解决**：手动带随机参数访问可绕过；长期修复是在 `PluginView.vue` 的 `iframeUrl` 上拼接时间戳参数，每次进入插件页都重新拉取。

```ts
const iframeUrl = computed(() => {
  const base = getBackendUrl()
  const name = encodeURIComponent(pluginName.value)
  return `${base || ''}/plugins_static/${name}/frontend/index.html?v=${Date.now()}`
})
```

#### 2、两套同名 Compose 互相接管导致数据“消失”与角色错乱

**现象**：打包桌面端后，题库数据“没了”，且账号显示为 `导数zyk` 但角色是普通用户，用户 ID 却是 2。
**原因**：仓库目录与 `%APPDATA%\oj-platform` 两套 compose 的项目名都是 `oj-platform`，桌面端启动时复用并重建同名容器，把 `postgres` 的挂载点从 `E:\github_project\oj-platform\data\postgres` 切换到了 `%APPDATA%\oj-platform\data\postgres`。旧数据文件并未丢失，只是容器挂错了目录。随后前端 `localStorage` 里的 `oj_token` / `oj_user` 由另一套库签发，导致显示信息与实际登录账号不一致。
**解决**：`docker inspect` 确认挂载来源后，`docker compose -f "%APPDATA%\oj-platform\docker-compose.yml" down` 停掉桌面端那套，回到仓库目录重新 `up`；前端清掉 `oj_token` / `oj_user` 后重新登录。长期需让两套库使用不同的 `JWT_SECRET`，并避免两套 compose 同时运行。

#### 3、插件注册表测试整体过期

**现象**：`test_plugin_registry.py` 9 个用例全部失败，报 `'PluginRegistry' object has no attribute 'register'`，另有 `/health` 返回 `KeyError: 'redis'`。
**原因**：e723433 重写 `PluginRegistry` 时删除了 `register()`、`_topological_order()`、`_plugin_classes` 实例属性，改用全局 `@register_plugin` 收集；b29478c 把 `/health` 简化为 `{"status": "ok"}`。测试自 3c08917 之后再未更新，一直在断言已不存在的接口。
**解决**：按当前架构重写测试——通过全局列表注册、`_build_instances()` 实例化，补齐 `discover_external` 跳过不完整目录、`collect_routers` 过滤禁用插件等用例，`/health` 断言改为仅校验 `status`。
