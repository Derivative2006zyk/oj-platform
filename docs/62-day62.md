# 第 62 天：全链路 E2E 自动化测试与插件导航栏控制

### 一、今日目标
- 引入 Playwright E2E 测试框架，告别手动点击验证的低效模式，覆盖登录与建题核心链路。
- 使用 Playwright 的 API Request 能力动态创建测试账号，解决测试环境数据依赖问题。
- 增加插件导航栏显示控制，允许用户在设置页选择是否将带有 UI 的插件显示在顶部导航栏，避免无界面插件污染菜单。

### 二、核心实现

#### 1、Playwright 自动化测试体系
- **环境安装与配置**：在 `frontend` 目录下执行 `npm init playwright@latest`。配置 `playwright.config.ts`，指定 `baseURL` 为 `http://localhost:5173`，并开启失败截图（`screenshot: 'only-on-failure'`）与失败重试视频，方便排查问题。
- **动态造数与认证测试（auth.spec.ts）**：在 `test.beforeAll` 阶段，使用 Playwright 提供的 `request` 对象，直接向后端 `POST /api/auth/register` 发送请求，动态注册一个带有时间戳唯一后缀的测试账号。接着在 UI 测试用例中，使用该账号去登录，断言页面跳转到 `/` 且渲染成功。
- **题库管理测试（problem.spec.ts）**：利用 `test.beforeEach` 在每个用例执行前先进行管理员登录，编写完整的 UI 交互流：点击“录入题目” -> 填写标题与描述 -> 提交表单 -> 断言列表页是否出现该题目。

#### 2、插件导航栏显示控制（show_in_nav）
- **后端扩展**：在 `admin_api.py` 新增 `PUT /admin/plugins/{name}/config` 接口，支持更新插件的 `config` 字典；在 `plugin_registry.py` 的 `get_ui_manifests` 中，从数据库 `config` 字段中提取 `show_in_nav`（默认 `True`）并返回给前端。
- **前端联动**：
  - 在 `stores/plugin.ts` 的类型定义中新增 `show_in_nav?: boolean`。
  - 在 `NavBar.vue` 的 `v-for` 循环中增加判断 `v-if="p.enabled !== false && p.show_in_nav !== false"`。
  - 在 `Settings.vue` 的“已安装插件”列表中，为有 UI 的插件提供复选框开关，勾选/取消时调用后端接口，即时刷新 `pluginStore`，实现无感切换。

### 三、踩坑记录

#### 1、依赖安装到了错误目录
**现象**：在项目根目录直接执行 `npm init playwright@latest`，导致根目录生成了 `package.json` 和 `tests`。
**解决**：删除根目录误生成的文件，明确该项目的 Web 前端根目录在 `frontend/`，需进入该目录重新初始化。

#### 2、测试账号无法登录
**现象**：测试脚本填入了预设的 `admin/admin123`，但登录失败停留在登录页。
**原因**：本地数据库未必存在该凭据。
**解决**：改用 API 动态注册账号（动态造数），保证测试隔离性与独立性。
