### 二、核心实现

#### 1、独立测试栈

开发栈占 8000/5432/6379，测试栈全部错开，且数据库用 `tmpfs` 保证每次重启都是干净的。

```yaml
name: oj-platform-test

services:
  postgres:
    image: postgres:15-alpine
    ports:
      - "55432:5432"
    tmpfs:
      - /var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U oj -d oj_platform_e2e"]

  redis:
    image: redis:7-alpine
    ports:
      - "56379:6379"
    tmpfs:
      - /data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]

  backend:
    ports:
      - "58000:8000"
    environment:
      ADMIN_KEY: e2e-key-change-me
```

`redis` 必须配 `healthcheck`，否则 `depends_on: condition: service_healthy` 会让 Compose 直接报 `has no healthcheck configured`。

#### 2、代理目标环境变量化

测试栈在 58000，开发栈在 8000。Vite 代理目标改为可注入：

```ts
const API_TARGET = process.env.VITE_PROXY_TARGET || 'http://127.0.0.1:8000'

const proxyConfig = {
  '/api': { target: API_TARGET, changeOrigin: true, ws: true },
  '/plugins_static': { target: API_TARGET, changeOrigin: true },
}
```

#### 3、Playwright 配置：端口隔离 + 禁止复用

```ts
const BASE_URL = process.env.E2E_BASE_URL || 'http://127.0.0.1:5174'
const PROXY_TARGET = process.env.VITE_PROXY_TARGET || 'http://127.0.0.1:58000'

webServer: {
  command: 'npm run dev -- --port 5174 --strictPort',
  url: BASE_URL,
  reuseExistingServer: false,   // 关键：绝不复用开发 server
  env: { VITE_PROXY_TARGET: PROXY_TARGET },
}
```

#### 4、globalSetup：一次注册，全局复用

E2E 用例共享同一个后端实例，如果每个用例各自注册，只有第一个能拿到 admin。改为 `globalSetup` 注册一次并保存 `storageState`：

```ts
await context.storageState({ path: AUTH_FILE })  // e2e/.auth/admin.json
```

`playwright.config.ts` 里 `use.storageState` 指向该文件，所有用例默认以管理员身份启动，无需重复注册。

#### 5、库非空时自动提权

测试库被反复运行时，首个用户已存在，新注册的只能是 `user`。`globalSetup` 检测到角色非 admin 时，直接改库：

```ts
function promoteToAdmin(username: string) {
  const sql = `UPDATE users SET role='admin' WHERE username='${username}'`
  execFileSync('docker', ['exec', PG_CONTAINER, 'psql', '-U', 'oj', '-d', PG_DB, '-c', sql])
}
```

提权后清空 `localStorage` 重新登录，让 `/api/users/me` 返回新角色。

#### 6、关键路径用例

| 文件 | 覆盖 |
|---|---|
| `auth.spec.ts` | 注册、登出后重新登录、错误密码拒绝 |

### 三、踩坑记录

#### 1、`__dirname` 在 ESM 下不可用

**现象**：`ReferenceError: __dirname is not defined in ES module scope`。
**原因**：`package.json` 有 `"type": "module"`，`.ts` 配置按 ESM 加载。
**解决**：

```ts
import { fileURLToPath } from 'node:url'
const __dirname = path.dirname(fileURLToPath(import.meta.url))
```

#### 2、`nodenext` 要求相对导入带扩展名

**现象**：`相对导入路径需要 ECMAScript 导入中的显式文件扩展名`。
**原因**：`tsconfig.node.json` 用 `module: "nodenext"`，但它只应管 `vite.config.ts` 与 `playwright.config.ts`。
**解决**：拆分 `tsconfig.e2e.json`，用 `moduleResolution: "bundler"`，允许无扩展名导入。

#### 3、`redis` 缺 healthcheck 导致依赖失败

**现象**：`container ... has no healthcheck configured`。
**解决**：给 `redis` 补 `test: ["CMD", "redis-cli", "ping"]`。

#### 4、注册邮箱格式被后端拒绝

**现象**：注册返回 422「输入格式不正确」。
**原因**：测试生成的邮箱为 `e2e_admin_xxx@e2e.local`，含下划线且域名不合法。
**解决**：统一用 `e2e<时间戳><序号>@example.com`。

#### 5、首个用户才是 admin，后续用例注册全是 user

**现象**：`注册用户 xxx 的角色是 user，不是 admin`。
**原因**：每用例各自注册，只有第一条能拿到 admin。
**解决**：`globalSetup` 注册一次 + 保存 `storageState`；库非空时走数据库提权。

#### 6、`alert()` 不是 DOM，`expectToast` 等不到

**现象**：题目实际创建成功，但用例超时找不到提示。
**原因**：`ProblemEdit` 保存成功用 `alert()` 并立即 `router.push('/')`，页面上没有可断言的提示元素。
**解决**：改用 `waitForURL(/#\/$/)` 作为成功信号；并用 `installDialogHandler` 统一处理 dialog。

#### 7、dialog 被重复处理

**现象**：`Cannot accept dialog which is already handled!`
**原因**：同一页面同时注册了 `page.on('dialog')` 与 `page.once('dialog')`。
**解决**：抽一个 `installDialogHandler(page, { accept })`，全局只注册一次。

#### 8、`getByRole('heading', { name: '题库' })` 命中两个元素

**现象**：strict mode violation，同时命中「题库」与「题库还是空的」。
**原因**：`name` 默认是子串匹配。
**解决**：加 `exact: true`。

#### 9、`setOffline` 不改变 `navigator.onLine`

**现象**：断网删除用例走进正常删除分支，没有触发离线提示。
**原因**：Playwright 的 `context.setOffline` 拦截请求，拉 `navigator.onLine` 仍为 `true`。
**解决**：改用 `context.route` 拦 `/api/**` 的非 GET 请求并 `abort('internetdisconnected')`，更接近真实断网。

#### 10、测试实际打到了开发后端

**现象**：测试库 `users` 表始终 0 行，但用例注册成功。
**原因**：`reuseExistingServer: !process.env.CI` 复用了开发中的 5173 服务，代理指向 8000。
**解决**：端口改 5174、`reuseExistingServer: false`、`VITE_PROXY_TARGET` 显式注入。

#### 11、hash 路由下改 `location.hash` 不触发视图切换

**现象**：`page.evaluate(() => window.location.hash = ...)` 后 iframe 未挂载。
**解决**：改用 `page.goto(完整 URL)` 做真实导航。

#### 12、`noauth` 参数到位但插件页仍显示工作区

**现象**：`iframe src` 含 `noauth=1`，但 `#authGate` 仍 hidden。
**原因**：`refreshAuthUI` 里 `el.authGate.hidden = loggedIn || !state.offline` —— 未登录且在线时两个区域都隐藏，页面空白。
**解决**：未登录时无条件显示 `authGate`。这本身是产品缺陷，测试正好暴露。
