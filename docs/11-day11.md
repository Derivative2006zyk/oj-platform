### 三、动态表单操作的关键实现

#### 1、选项的 key 自动分配

```typescript
function addOption() {
  const key = String.fromCharCode(65 + form.options.length) // A, B, C...
  form.options.push({ key, content: '', is_correct: false })
}
```

`65` 是字符 `A` 的 ASCII 码。长度为 0 时给 `A`，为 1 时给 `B`，以此类推。

删除后重新分配 key：

```typescript
function removeOption(idx: number) {
  form.options.splice(idx, 1)
  form.options.forEach((opt, i) => {
    opt.key = String.fromCharCode(65 + i)
  })
}
```

#### 2、正确答案的单选逻辑

```typescript
function setCorrectOption(idx: number) {
  form.options.forEach((opt, i) => {
    opt.is_correct = i === idx
  })
}
```

本项目选择题为单选题。若需支持多选，可改为 checkbox，并去掉这个函数。

#### 3、填空题答案的文本格式

表单里用户输入 `3|三次`，提交时拆分为 `["3", "三次"]`：

```typescript
correct_answers: String(b.answers_text || '')
  .split('|')
  .map((s: string) => s.trim())
  .filter((s: string) => s)
```

编辑回填时反向拼接：

```typescript
answers_text: Array.isArray(b.correct_answers)
  ? b.correct_answers.join('|')
  : ''
```

#### 4、子项目 sort_order 自动维护

添加子项目时 `sort_order` 为当前长度加 1，提交时按索引重新赋值，避免顺序错乱。

#### 5、参考资源过滤

提交前过滤掉空标题或空 URL：

```typescript
reference_links: (sp.reference_links || []).filter((r: any) => r.title && r.url)
```

### 四、图片上传

#### 1、上传逻辑

```typescript
async function handleImageUpload(event: Event) {
  const input = event.target as HTMLInputElement
  if (!input.files || input.files.length === 0) return

  const file = input.files[0]
  uploadingImage.value = true
  try {
    const problemId = isEdit.value ? Number(route.params.id) : undefined
    const result = await uploadImage(file, problemId)
    form.description += `\n\n![图片](${result.url})\n\n`
    alert('图片已上传，Markdown 语法已插入描述末尾')
  } catch (e: any) {
    const msg = e.response?.data?.detail || e.message || '上传失败'
    alert('上传失败：' + msg)
  } finally {
    uploadingImage.value = false
    input.value = ''
  }
}
```

上传成功后，把 Markdown 图片语法追加到描述末尾。用户可在文本域中调整位置。

#### 2、问题：图片显示为占位符，F12 报 404

**现象**：数据库描述里是 `![图片](/api/image/3)`（单数），但后端路由注册的是 `/api/images/{id}`（复数）。浏览器补全为 `http://localhost:5173/api/image/3`，Vite 代理转发到后端 8000，后端找不到该路径，返回 404。

**原因**：早期上传接口返回的 `url` 字段写成了单数 `/api/image/{id}`，插入数据库的 Markdown 就是单数 URL。

**排查步骤**：

```
docker exec -it oj-platform-postgres-1 psql -U oj -d oj_platform -c "SELECT id, description FROM problems WHERE description LIKE '%api/image/%';"
```

**批量修复**：

```
docker exec -it oj-platform-postgres-1 psql -U oj -d oj_platform -c "UPDATE problems SET description = REPLACE(description, '/api/image/', '/api/images/') WHERE description LIKE '%/api/image/%';"
```

### 五、三层防护，彻底避免单复数问题

#### 1、数据层：修正数据库

用上面的 REPLACE 语句批量修正。

#### 2、后端层：修正上传接口并加兼容路由

打开 `backend/app/plugins/problem_plugin/image_api.py`，上传接口的返回：

```python
return {
    "id": image.id,
    "url": f"/api/images/{image.id}"
}
```

**必须用复数 `images`**。

加兼容路由：

```python
@router.get("/image/{image_id}")
async def get_image_legacy(image_id: int, db: AsyncSession = Depends(get_db)):
    """兼容旧 URL 的图片访问接口（单数）"""
    return await get_image(image_id, db)
```

放在 `get_image` 定义之后。

#### 3、前端层：渲染时字符串替换

打开 `frontend/src/components/MarkdownRenderer.vue`：

```typescript
const rendered = computed(() => {
  if (!props.content) return ''
  // 兼容旧数据：把单数 /api/image/ 替换为复数 /api/images/
  const content = String(props.content).replace(/\/api\/image\//g, '/api/images/')

})
```

### 六、踩坑：marked renderer 与新版签名不兼容

#### 1、问题

在 `utils/marked.ts` 中尝试自定义 renderer 兼容单数 URL：

```typescript
renderer.image = function (href: string, title: string | null, text: string) {
  if (href && href.startsWith('/api/image/')) {
    href = href.replace('/api/image/', '/api/images/')
  }
  return originalImage(href, title, text)
}
```

浏览器报错：

```
Uncaught (in promise) TypeError: href.startsWith is not a function
```

#### 2、原因

新版 marked（v12+）的 `renderer.image` 第一个参数是 **token 对象** `{href, title, text}`，不是字符串。旧版才是 `(href, title, text)`。

#### 3、解决

既然 `MarkdownRenderer.vue` 已在渲染前做了字符串替换，`utils/marked.ts` 里的自定义 renderer 是多余的。直接删除即可：

```typescript
import { marked } from 'marked'
import { markedHighlight } from 'marked-highlight'
import hljs from 'highlight.js'
import 'highlight.js/styles/github.css'

marked.use(
  markedHighlight({
    langPrefix: 'hljs language-',
    highlight(code, lang) {
      if (lang && hljs.getLanguage(lang)) {
        try {
          return hljs.highlight(code, { language: lang }).value
        } catch (e) {
          console.error('高亮失败：', e)
        }
      }
      return hljs.highlightAuto(code).value
    }
  })
)

export { marked }
```

#### 4、通用经验

**处理简单字符串替换**时，优先在渲染前的字符串层面做，而不是在渲染器的回调函数里做。原因：

- 字符串替换跨版本兼容
- 渲染器的签名在不同版本间可能变化
- 字符串替换更直观，容易调试

### 八、动态表单的内存管理

`v-for` 使用 `:key="idx"` 而非对象本身。删除中间项后，Vue 通过索引复用 DOM，可能造成输入内容错位。

更严谨的写法是为每个条目加唯一 ID：

```typescript
form.test_cases.push({ id: Date.now(), input_data: '', expected_output: '', is_example: true })
```

然后 `:key="tc.id"`。本项目数据量小，暂用索引。

### 九、提交字段按题型过滤

`buildSubmitData` 根据题型决定哪些字段有值：

```typescript
if (form.type === 'algorithm') {
  base.test_cases = form.test_cases.map(tc => ({...}))
  base.options = null
  base.blanks = null
  base.subprojects = []
} else if (form.type === 'choice') {
  base.test_cases = []
  base.options = form.options.map(o => ({...}))
  base.blanks = null
  base.subprojects = []
}
// ...
```

后端 Pydantic 模型：

```python
options: Optional[List[dict]] = None
blanks: Optional[List[dict]] = None
test_cases: List[TestCaseCreate] = []
subprojects: List[SubprojectCreate] = []
```

- `options`、`blanks` 可传 null
- `test_cases`、`subprojects` 默认是数组，传 `[]` 表示无

### 十二、注意事项

#### 1、v-model.number 强制数字类型

```vue
<select v-model.number="form.category_id">
<select v-model.number="form.difficulty">
```

避免提交时数字变成字符串导致 422。

#### 2、动态表单的防御性回填

```typescript
form.test_cases = Array.isArray(detail.test_cases)
  ? detail.test_cases.map(tc => ({...}))
  : []
```

若 `detail.test_cases` 是 undefined，回退为空数组，避免 `Cannot read property 'map' of undefined`。

#### 3、选择题校验

```typescript
if (form.type === 'choice') {
  if (!Array.isArray(form.options) || form.options.length < 2) {
    alert('选择题至少需要 2 个选项')
    return
  }
  if (!form.options.some(o => o.is_correct)) {
    alert('请勾选一个正确答案')
    return
  }
}
```

#### 4、图片上传的 problem_id 参数

编辑模式传 `problemId`，新建模式传 `undefined`。后端会验证题型是否允许图片（choice 和 fill_blank 会被拒绝）。

#### 5、图片描述插入位置

当前追加到描述末尾。若描述较长，用户需手动剪切并移动到合适位置。更友好的是在光标位置插入，本项目暂不实现。

#### 6、三层图片 URL 防护

| 层 | 措施 |
|---|---|
| 数据层 | 用 SQL REPLACE 批量修正历史数据 |
| 后端层 | 上传接口返回复数 URL；加兼容单数路由 |
| 前端层 | 渲染前字符串替换单数 URL |

#### 7、marked renderer 与版本的兼容

新版 marked（v12+）的 `renderer.image` 参数是 token 对象。若需自定义 renderer，应检查 marked 版本，并写兼容两版的函数。本项目采用更简单的方式——字符串替换。

#### 8、Vite 代理的生效条件

修改 `vite.config.ts` 后必须重启 Vite。可以在 Vite 启动输出中确认配置已加载。

#### 9、编辑模式下题型禁用

```vue
<select v-model="form.type" :disabled="isEdit">
```

与后端约定一致。若允许修改题型，需要删除旧的子表数据、清空 JSONB 字段，复杂度较高，本项目暂不支持。

#### 10、提交按钮的禁用

`submitting` 为 true 时按钮禁用，避免重复提交。请求完成后 finally 块中恢复。

#### 11、调试技巧

保存失败时打开 F12 → Network，查看 `/api/admin/problems` 请求的 Payload 和 Response：

- Payload 应包含正确的 JSON
- Response 的 `detail` 会给出具体的字段错误

#### 12、图片 URL 的正确格式

| 格式 | 用途 |
|---|---|
| `/api/images/1` | 后端返回，Markdown 中使用 |
| `http://localhost:8000/api/images/1` | 直接访问后端 |
| `http://localhost:5173/api/images/1` | Vite 代理转发后的 URL |

Markdown 中始终用相对路径，由浏览器基于当前域名补全。

### 十五、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 选择题保存后选项丢失 | 提交时 options 未传 | 检查 buildSubmitData |
| 编辑回填时测试用例丢失 | 详情接口只返回示例 | 详情只返回 is_example=True 的用例，全量需另接口 |
| 图片上传 400 | 关联的题型为 choice 或 fill_blank | 选择其他题型或不关联 |
| 填空题答案格式错误 | `|` 被当作 Markdown 表格分隔符 | 表单输入 `|` 是文本字符，不影响提交 |

| 提交后 422 | 某字段类型不对 | F12 查看 Payload，对照后端 schema |
| 图片 404（单数 URL） | 数据库中是 `/api/image/` | 用 SQL REPLACE 修正为复数 |
| `href.startsWith is not a function` | marked 新版 renderer 签名 | 删除自定义 renderer，用字符串替换 |
| 保存时提示"题目不存在" | 编辑模式下 id 不存在 | 通过列表页点击进入 |
| 选项 key 不连续 | 删除中间项未重排 | removeOption 中已重排 |
