# 第 60 天：离线写操作支持与本地操作队列

### 一、今日目标
- 实现真正的离线优先（Offline-First）闭环：断网状态下不仅能看题，还能修改题目和提交答案。
- 构建轻量级的本地操作队列（Operation Queue），将断网时的修改暂存至浏览器本地。
- 在网络恢复时自动重放队列中的请求，实现静默同步。
- 修复 Vite 代理在断网时返回 502 错误导致离线队列拦截失败的问题，并修复插件路由警告。

### 二、核心实现

#### 1、本地操作队列封装（utils/offline-queue.ts）
- 定义了 `OfflineAction` 数据结构（包含 method, url, data, headers）。
- 提供 `enqueueAction` 将失败的写请求压入 `localStorage`。
- 提供 `processQueue` 函数，在监听到 `window.addEventListener('online')` 时触发，遍历队列并重新发起 Axios 请求。
- 针对乐观锁（Version），如果重放请求返回 `409 Conflict`，弹出严重警告，告知用户离线修改已被覆盖。

#### 2、API 层的网络异常拦截（problem.ts & submission.ts）
- **修改题目（updateProblem）**：捕获异常时，除了 409 版本冲突外，将超时、断网、以及 Vite 代理返回的 `502/503` 全部判定为离线。将请求丢进队列，并伪造成功返回。
- **新建/删除题目（createProblem/deleteProblem）**：这类操作极度依赖服务器状态，不支持离线。拦截网络错误后，抛出友好的中文提示，避免前端弹出 502 错误。
- **提交答案（submitCode）**：拦截网络错误，将提交数据压入队列。同时**伪造一个本地提交对象**（`id` 为负数，`status` 为 `OFFLINE_PENDING`）返回给 UI 层，防止页面报错卡死。

#### 3、页面层的 UI 适配
- **ProblemEdit.vue**：断网时读取本地详情缓存回填表单；判断 `updateProblem` 的返回值，如果是离线保存，提示用户已存入本地队列。
- **ProblemDetail.vue**：
  - `statusLabel` 增加 `OFFLINE_PENDING` 映射，显示为“待同步(离线)”。
  - 四个提交函数（算法、选择、填空、证明）增加拦截判断：如果返回离线状态，弹窗提示并中止后续的 WebSocket 订阅和列表刷新。

#### 4、修复插件路由警告
- 修改 `scripts/pack_ocr_plugin.py` 中的 `manifest.json`，将 `route_path` 从 `/ocr` 改为 `/plugin/ocr_plugin`，消除 Vue Router 找不到匹配路径的警告。

### 三、踩坑记录

#### 1、Vite 代理的 502 拦截
**现象**：断网保存时，提示“保存失败：Request failed with status code 502”，离线队列没有生效。
**原因**：Vite dev server 连不上后端时，直接返回了 HTTP 502，导致 Axios 抛出了带有 `response` 的错误，被原先的网络错误判断逻辑漏掉了。
**解决**：在 API 层修改拦截条件，将 `502` 和 `503` 也认定为离线状态，触发本地队列。

#### 2、离线提交的伪造状态
**现象**：如果提交答案报错，页面因为 `currentSubmission.value` 为空，无法渲染结果面板。
**解决**：在 `submitCode` 拦截网络错误后，构造一个假的 `SubmissionDetail` 对象返回。这样页面能正常渲染出“待同步”的状态卡片，用户感知良好。
