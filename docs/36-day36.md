### 二、数据模型改动

| 列名 | 类型 | 说明 |

| submission_kind | String(20) | code / choice / fill_blank |
| answer_data | JSONB | 选择题、填空题的答案 |

迁移脚本：`add_submission_kind_and_answer_data_to_submissions`。

### 三、Schema 改动

`SubmissionCreate`：

- `code: Optional[str] = None`
- `answer_data: Optional[dict] = None`
- `model_validator` 按 `language` 推导题型，校验互斥字段

`SubmissionDetail` 新增字段：

- `submission_kind: str`
- `answer_data: Optional[dict]`
- `code` 改为 `Optional[str]`

### 四、判题通道

选择题**同步判题**，不入 arq 队列、不走 Docker。

流程：

```text
POST /api/submissions
  → create_submission (status=PENDING)
  → submission_kind == 'choice'
  → judge_inline(db, sub)
  → 写回 AC / WA
  → 发布 submission.judged 事件
  → 返回终态
```

算法题仍入 arq 队列，异步判题。

### 五、选择题判题器

`judge_choice(answer_data, options)`：

- 单选：`{"selected": "A"}`
- 多选：`{"selected": ["A", "B"]}`（预留）
- 空答案 → WA
- 未配置正确项 → RE
- 全对 → AC

`runtime_ms` 固定 0。前端对 `runtime_ms > 0` 才显示耗时。

### 六、API 层分派

```python
sub = await service.create_submission(db, current_user.id, data)

if sub.submission_kind == "code":
    await enqueue("judge_submit", submission_id=sub.id)
else:
    await service.judge_inline(db, sub)

return sub
```

### 七、Worker 加固

`judge_submit` 增加防御：

```python
if getattr(sub, "submission_kind", "code") != "code":
    return
```

防止历史队列里的非 code 任务误入 Docker 判题。

### 十、踩坑记录

#### 1、schemas 文件覆盖不全

**现象**：`ImportError: cannot import name 'SubmissionDetail'`，后端容器一直 Restarting。

**原因**：替换 `schemas/submission.py` 时只保留了 `SubmissionCreate`，删掉了 `SubmissionDetail` 与 `SubmissionListResponse`，API 层 import 失败。

**解决**：三个类必须同时存在。这个文件不能分次覆盖。

#### 2、重建后端不是 restart

**现象**：改完 schema 后，请求仍报 `Field required`。

**原因**：`docker compose restart backend` 只重启进程，不重新加载源码。

**解决**：`docker compose build backend && docker compose up -d backend`。

#### 3、算法题排队中

**现象**：提交算法题后一直 PENDING。

**原因**：worker 未启动，或启动后未加载新代码。

**解决**：单独终端跑 `arq app.plugins.judge_plugin.worker.WorkerSettings`，修改 worker.py 后重启 worker。
