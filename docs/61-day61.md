# 第 61 天：前端体验深度打磨（极暗模式与全局状态组件）

### 一、今日目标
- 利用 Design Token 体系扩展暗色模式（Dark Mode），采用极暗终端风配色，支持一键切换与持久化。
- 针对性适配代码编辑器（Monaco）和 Markdown 代码块，解决暗色模式下的“刺眼白块”问题。
- 封装轻量级全局 Toast 提示组件，替代体验极差的浏览器原生 `alert`。
- 修复部分网络异常（如 Vite 代理 ECONNREFUSED）和路由配置带来的控制台噪音。

### 二、核心实现

#### 1、极暗终端风配色体系（tokens.css）
- 在 `[data-theme="dark"]` 变量组中，将背景页设为 `#0a0a0a`（纯黑），卡片背景设为 `#151515`（深灰）。
- 加入 `color-scheme: dark;` 声明，防止浏览器或插件（如 Chrome 的 Force Dark Mode）强行反转颜色导致字体和背景冲突。
- 使用 CSS 属性选择器 `[data-theme="dark"]` 全局强制覆盖 `input`、`textarea`、`select` 的背景色与文字颜色。

#### 2、编辑器与渲染器的暗色联动
- **Monaco Editor**：在 `CodeEditor.vue` 中使用 `MutationObserver` 监听 `<html>` 节点的 `data-theme` 属性变化。一旦检测到切为暗色，调用 `monaco.editor.setTheme('vs-dark')` 动态切换。同时，移动端的原生 `<textarea>` 也全面替换为 CSS 变量控制颜色，并统一外部容器边框。
- **Markdown**：在 `MarkdownRenderer.vue` 中，针对 `:deep(pre)` 和 `:deep(code)` 增加 `[data-theme="dark"]` 的专属样式，将代码块背景替换为纯黑并加灰色边框。

#### 3、全局 Toast 轻提示组件
- 新建 `utils/toast.ts`，利用原生 DOM API 动态创建浮动提示框。
- 支持 `info`、`success`、`error` 三种状态，带有平滑的入场和退场动画，3 秒后自动销毁，不阻塞页面。

#### 4、离线初始化与路由修正
- 修复了 `ProblemEdit.vue` 的 `onMounted` 逻辑。将原先的 `Promise.all` 拆分为独立的 `try-catch` 块，确保断网时优先读取缓存，不阻塞页面初始化。
- 修改 `scripts/pack_ocr_plugin.py`，将插件路由从 `/ocr` 修正为 `/plugin/ocr_plugin`，彻底消除 Vue Router 警告。
- 为 `ProblemDetail.vue` 的提交历史卡片增加了暗色专属覆盖，解决状态标签在暗色下的突兀感。

### 三、踩坑记录

#### 1、暗色模式下部分组件依然泛白
**现象**：全局背景变黑了，但部分代码输入框、历史标签的背景依然是大白块。
**原因**：第三方组件（Monaco）有自己的独立主题系统，不读取 CSS 变量；部分原生 `<input>` 在特定浏览器下有强制的默认背景色。
**解决**：对于 Monaco，在 JS 层面监听并切换主题；对于原生元素和局部 UI，使用 `!important` 在 `[data-theme="dark"]` 作用域下强制覆盖颜色变量。

#### 2、Vite 代理的 ECONNREFUSED 报错
**现象**：刚启动 Docker 时，前端控制台狂报 `AggregateError [ECONNREFUSED]`。
**原因**：Docker 容器（尤其是 PostgreSQL）启动需要十几秒，期间 Vite 转发请求直接被拒绝。
**解决**：属于本地开发环境的正常现象，等后端打印出 `Application startup complete` 后刷新即可。
