# 第 63 天：AI 通用接口层架构与流式生成器深度解析

### 一、 今日核心目标与架构思维

在传统的 CRUD 系统中，HTTP 请求是“请求-响应”模式：客户端发送请求，服务端处理完毕后一次性返回数据。但大语言模型（LLM）的推理是逐字生成的，如果等待全部生成完毕再返回，用户将面临长达十几秒的“白屏”等待，体验极差。

因此，今天的核心任务是在系统中构建一条**全链路的实时流式数据管道**：
1. **后端**：利用 Python 的 `AsyncIterator` 和 FastAPI 的 `StreamingResponse` 构建 SSE (Server-Sent Events) 接口，实时转发大模型的字符流。
2. **前端**：利用浏览器的 `fetch` + `ReadableStream` API，实时读取底层 TCP 数据包，并通过 `TextDecoder` 解码，实现极致的“打字机”效果。
3. **安全与隔离**：设计基于账号的多 Profile 配置管理，确保 API Key 不泄露。

---

### 二、 后端核心一：AI 通用引擎的抽象与多态

为了不让代码与特定厂商（如 DeepSeek、OpenAI）深度绑定，我们采用了经典的**适配器模式（Adapter Pattern）**。

#### 1. 抽象基类设计
在 `backend/app/plugins/ai_plugin/backend.py` 中，我们定义了 `AIBackend`：

```python
from abc import ABC, abstractmethod
from typing import AsyncIterator, List, Dict

class AIBackend(ABC):
    @abstractmethod
    async def chat_stream(self, messages: List[Dict[str, str]]) -> AsyncIterator[str]:
        """流式对话，返回一个异步生成器，产出文本块"""
        pass
```
**关键点**：返回值必须是 `AsyncIterator[str]`。这意味着任何实现了这个接口的类，都必须支持 `async for` 语法，这是后端流式输出的基础。

#### 2. 零配置测试引擎（MockAIBackend）
为了保证前端 UI 在没有任何 API Key 的情况下也能进行开发联调，我们实现了一个 Mock 引擎：
```python
class MockAIBackend(AIBackend):
    async def chat_stream(self, messages: List[Dict[str, str]]) -> AsyncIterator[str]:
        reply = "（这是一条模拟回复）我收到了你的问题。"
        for char in reply:
            yield char
            await asyncio.sleep(0.05) # 模拟网络延迟
```
这个生成器不会阻塞主线程，每次 `yield` 都会将控制权交还给事件循环，从而完美模拟真实的打字机推流。

#### 3. 主流大模型适配器（OpenAICompatibleBackend）
目前国内绝大多数大模型（DeepSeek、智谱、千问）都兼容 OpenAI 的 API 格式。我们利用 `httpx` 的异步流式读取功能对接：

```python
import httpx, json

class OpenAICompatibleBackend(AIBackend):
    async def chat_stream(self, messages: List[Dict[str, str]]) -> AsyncIterator[str]:
        headers = {"Authorization": f"Bearer {self.api_key}", "Content-Type": "application/json"}
        data = {"model": self.model, "messages": messages, "stream": True}
        
        async with httpx.AsyncClient(timeout=60.0) as client:
            # 开启流式请求
            async with client.stream("POST", f"{self.base_url}/chat/completions", headers=headers, json=data) as response:
                # 逐行读取 TCP 数据包
                async for line in response.aiter_lines():
                    if line.startswith("data: "):
                        data_str = line[6:]
                        if data_str == "[DONE]":
                            break
                        chunk = json.loads(data_str)
                        delta = chunk["choices"][0]["delta"].get("content", "")
                        if delta:
                            yield delta
```
**底层原理剖析**：
- `client.stream` 会返回一个上下文管理器，此时 HTTP 连接尚未关闭，处于挂起状态。
- `response.aiter_lines()` 是一个异步迭代器，它会监听底层的 TCP 缓冲区，一旦接收到换行符 `\n`，就会产出一行数据。这确保了只要大模型吐出一个字，我们就能立刻接收到，而不是等全部生成完毕。

### 三、 后端核心二：FastAPI 流式生成器与 SSE 协议

AI 引擎产出了字符流后，我们需要通过 Web 接口（基于 HTTP 协议）将其推给前端。由于我们的客户端是 Vue 浏览器，最成熟的方案是 **SSE (Server-Sent Events)**。

#### 1. SSE 协议规范
SSE 规定，服务器返回的流必须具有特定的格式：
- 响应头必须是 `Content-Type: text/event-stream`。
- 每条消息以 `data: ` 开头，以双换行符 `\n\n` 结尾。

#### 2. 构建 FastAPI StreamingResponse
在 `api.py` 中，我们定义了如下路由：

```python
from fastapi.responses import StreamingResponse

@router.post("/chat")
async def chat(req: ChatRequest, ...):
    # 1. 实例化具体的大模型引擎
    backend = OpenAICompatibleBackend(...) if api_key else MockAIBackend()
    
    # 2. 定义内部异步生成器
    async def event_generator():
        try:
            # 【核心机制】发送一个空的心跳，立刻刷新 HTTP 响应头，防止 Nginx 或 Vite 代理因为超时挂断连接
            yield ": keep-alive\n\n"
            
            # 3. 消费 AI 引擎的流
            async for chunk in backend.chat_stream(messages):
                # 处理多行文本，SSE 要求每一行都必须有 data: 前缀
                for line in chunk.split('\n'):
                    yield f"data: {line}\n"
                # 每条完整的消息后需要两个换行符
                yield "\n"
        except Exception as e:
            # 异常兜底：如果大模型鉴权失败或网络中断，把错误信息包装成 SSE 格式推给前端
            yield f"data: 【流式异常】{str(e)}\n\n"
        finally:
            # 发送结束信号
            yield "data: [DONE]\n\n"

    # 4. 返回流式响应
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```
**技术亮点**：
- **心跳保活**：`: keep-alive\n\n` 是一行注释，前端解析时会忽略，但它的作用是强制刷新 HTTP Buffer，解决长时间无数据推送导致连接被代理服务器（如 Vite）掐断的问题。
- **异常流化**：将原本会抛出 500 异常的 `try-except` 放在生成器内部，把报错直接变成流推给前端，极大降低了排查难度。

### 四、 前端核心：ReadableStream 解析与流式打字机

前端没有使用 `EventSource`（因为它不支持 POST 请求和自定义 Header），而是使用了更底层的 `fetch` API 结合流读取器。

#### 1. 获取流读取器
```typescript
const response = await fetch(url, { method: 'POST', ... })
// 获取底层字节流的读取器
const reader = response.body?.getReader()
const decoder = new TextDecoder('utf-8')
```

#### 2. 极为关键的 Buffer 缓冲机制
网络传输的 TCP 包并不是按照字符边界切割的。比如，一个汉字“流”可能在第一次 TCP 包中被截断了一半，下一次才收到另一半。如果直接 `decoder.decode(value)` 会导致乱码。
因此，必须使用 `{ stream: true }` 配合缓存区：

```typescript
let buffer = ''
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  
  // 解码新收到的字节块，并追加到缓存区
  buffer += decoder.decode(value, { stream: true })
  
  // 按换行符分割，但最后一个可能是不完整的（比如只收到一半的 JSON）
  const lines = buffer.split('\n')
  // pop() 把最后一段未完结的字符串拿出来，留在 buffer 里等待下一次拼接
  buffer = lines.pop() || '' 
  
  // 处理完整的行
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      let data = line.slice(6).replace(/\r$/, '')
      
      // 结束符判断
      if (data.trim() === '[DONE]') {
        onComplete()
        return
      }
      
      // 将后端的转义换行恢复
      data = data.replace(/\\n/g, '\n')
      onChunk(data) // 触发 Vue 视图更新
    }
  }
}
```

#### 3. 前端 Vue 的状态更新
在 `AIChatPanel.vue` 中，`onChunk` 回调将直接操作响应式变量：
```typescript
messages.value[idx].content += chunk
```
Vue 底层会触发 Diff 算法，并将新增的字符拼接到 DOM 节点上，这就形成了极为丝滑的打字机效果。

### 五、 基于账号的云端 Profile 管理

为了跨设备同步且保证 API Key 的隔离，我们设计了 `user_ai_configs` 表。
- **数据库结构**：`user_id`（主键）、`config`（JSONB 类型）。
- **数据结构设计**：
```json
{
  "current_profile": "DeepSeek 默认",
  "profiles": {
    "DeepSeek 默认": { "api_key": "sk-...", "base_url": "...", "model": "..." }
  }
}
```
- **鉴权流程**：前端调用 `PUT /api/plugins/ai/config` 时，后端利用 `Depends(get_current_user)` 从 JWT Token 解析出 `user_id`，确保每个用户只能读写自己的配置。

### 六、 排雷与工程化沉淀

#### 1. 流式下的 Markdown 渲染断层
由于大模型的输出是碎片化的，如果每次收到一个字符就去触发 MathJax 公式渲染，系统会因为公式还未闭合（比如只有 `\(` 没有 `\)`）而疯狂报错。
**解决**：给 `MarkdownRenderer.vue` 增加 `streaming` 属性，在整个流接收完毕前，仅渲染基础 Markdown。接收完毕后，才触发 MathJax 的 `typesetPromise` 进行全局解析。

#### 2. Docker 状态文件陷阱
在容器内执行 `alembic revision --autogenerate` 生成的数据表迁移文件，如果在重启前没有通过 `docker cp` 复制到宿主机，容器一重启就会丢失，导致数据库版本记录断裂，后端无限崩溃（引发 Vite 代理报 502）。

#### 3. 前端弹窗的自由拖拽
放弃了 CSS 自带的 `resize`，利用 `mousedown`、`mousemove`、`mouseup` 手写了左上角的拖拽逻辑，动态计算鼠标位移的 `deltaX/Y`，实时调整面板的 `width` 和 `height`。
